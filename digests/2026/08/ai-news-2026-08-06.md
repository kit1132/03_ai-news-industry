### 1. Claude Opus 4.1 が本日 API 退役 — 固定したモデル ID が今日からエラーになる

**要点**: Anthropic が Claude Opus 4.1 を 8/5 に API 退役させ、GitHub Copilot も Claude Sonnet 4.6 を 9/1 に非推奨化する。前提は「モデル ID は当面使える」から「固定 ID を四半期ごとに棚卸しする」へ変わる。

**詳細**: `claude-opus-4-1-20250805` は **8/5 に hard retirement** となり、以降このモデル ID へのリクエストはエラーを返す。非推奨の告知は 6/5 で、告知から60日という Claude Opus 4 と同じ猶予幅だった。推奨移行先は `claude-opus-4-8`。Anthropic は後継投入から60〜90日で旧モデルを退役させる周期で運用している。GitHub 側は 7/31 の Changelog で、**Claude Sonnet 4.6 を 9/1 に Copilot の全体験で非推奨化**すると告知した。対象は Copilot Chat・インライン編集・ask / agent モード・コード補完で、年額プランの個人契約者にはSonnet 系を残すため引き続き提供される。Copilot Enterprise の管理者は代替モデルへのアクセスをモデルポリシー側で有効化する必要がある。08-04 収録の「7/31 付 Gemini 2.5 Pro / Gemini 3 Flash 非推奨」と同じ Changelog の続きで、Copilot 側のモデル選択肢は2カ月で3本入れ替わることになる。

### 2. ホワイトハウスの AI 評価枠組みが非公開で確定 — 中身を知るのは参加企業だけになる

**要点**: 8/4 の会合で EO 14409 の任意フレームワークが確定したが、ホワイトハウスは内容を公表しない方針である。前提は「8月に公開ルールが出る」から「参加企業しか条件を知らない任意制度」へ変わる。

**詳細**: 6/2 の大統領令 EO 14409 が課した60日期限（8/1）について、ホワイトハウスは 8/3 に期限を満たしたと表明した。8/4 火曜のスタッフレベル会合には **Meta / Nvidia / Microsoft / OpenAI / Anthropic / Google と中小企業を含む約12社**が出席し、議論を締めくくった。枠組みの内容は、特定のフロンティアモデルへ政府が公開前**最大30日**の早期アクセスを得られる一方、これを義務的なライセンス制度や事前審査制度として使うことはできない、というもの。どのモデルを「frontier model」と位置づけるかを政府と企業が共同で判定するプロセスも含む。**公表しない理由は EO 自体にある** — サイバー能力を評価するベンチマークプロセスは EO 上で機密（classified）と明示されており、任意フレームワークの公表義務は課されていない。企業側は会合の直前まで中身を見ていなかったと Semafor が報じている。07-31 以降「期限超過・未公表」として継続ウォッチしていた項目は、公表されないまま確定という形で決着した。参加しない企業・研究者・同盟国は判定条件を知る手段がない。

### 3. 第9巡回区が Perplexity への差止を破棄 — アクセス主体はエージェントでなく利用者と判断された

**要点**: 米第9巡回区控訴裁が 8/4、Amazon の CFAA 仮差止を破棄した。サーバーにアクセスしたのは開発者でなく利用者との判断。前提は「サイト側は CFAA でエージェントを排除できる」から「排除には別の法的根拠が要る」へ変わる。

**詳細**: Amazon は2025年末に Perplexity を提訴し、AI 買い物エージェント Comet がパスワード保護された顧客アカウントへ不正にアクセスしていると主張していた。2026年3月に連邦地裁が仮差止を認め、Comet による Amazon 上での購入を差し止めていた。3人の判事パネルは、**Comet は利用者自身のブラウザが取得したスクリーンショットを受け取っているだけ**であり、Perplexity は Amazon のコンピュータに「アクセス」していないと判断した。CFAA の文言に曖昧さがある場合は責任を否定する方向に解釈する rule of lenity を適用している。判決は **AI エージェントへの責任帰属を直接扱った判例がほとんど存在しない**ことを明示した。ただし Amazon の商標上の請求と州法上の請求は存続するため、紛争そのものは続く。EFF は「ウェブブラウザを作ることは CFAA 違反にならない」として判断を支持している。エージェントに業務サイトを操作させる構成では、相手サイト側の遮断手段が利用規約・技術的ブロック・州法側へ移る。

## 開発者ツール

- **Claude Code 2.1.222 が権限まわりの抜けをまとめて塞いだ** — 8月4日リリース。2.1.221 と合わせ、エージェントに権限を委ねる構成で効く修正が並んでいる。
  - worktree 分離セッションとそのサブエージェントが、main チェックアウトに対して破壊的な git コマンドを実行できた問題を修正した。分離はすべてのセッション種別でファイル編集と Bash に適用される
  - PreToolUse の auto-allow フックが、バックグラウンドエージェントのタスクでツール制限を迂回できた問題を修正した
  - zsh の `[[ ]]` 正規表現条件を使って Bash の権限チェックを迂回し隠しコマンドを実行できた問題を、2.1.221 で修正した
  - Remote Control の自動起動を、リポジトリ側の `.claude/settings.json` / `.claude/settings.local.json` からは有効化できなくした。ユーザースコープの `/config` からのみ設定する
  - auto モードで `SendMessage` 経由の他セッション宛メッセージが、送信前に権限分類器で評価されるようになった。`ultraplan` は削除された

  本リポジトリのように `.claude/settings.json` を版管理しているプロジェクトは、Remote Control の設定場所が変わる点を確認する必要がある。
  - https://code.claude.com/docs/en/changelog
