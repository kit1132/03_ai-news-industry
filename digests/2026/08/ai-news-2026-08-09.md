### 1. Claude Code の auto mode が 8/14 に既定化 — 承認ダイアログを統制点として設計した運用が5日後に崩れる

**要点**: Anthropic が 8/14 から Pro / Max / Team の既定パーミッションモードを auto mode へ切り替える。前提は「危険な操作は人の承認で止める」から「人は 13.6% しか止められないので分類器で止める」へ変わる。

**詳細**: 8/7 の告知。auto mode はツール呼び出しを分類器へ通し、不可逆・破壊的・環境外へ向かう操作だけを止めて、それ以外の承認プロンプトを省く動作モードにあたる。Anthropic は有料の職業テスター **1,053人** による対照実験を根拠に挙げている。

  - 人によるレビューが危険なコマンドを捕捉できたのは **13.6%**、同じ操作を auto mode の分類器は **89%** 止めた
  - 人の捕捉率はセッションが長いほど落ち、**プロンプト50件以降は約5%** まで下がる
  - Claude Code 利用者は承認プロンプトの **97%** を承認しており、反射的に通している疑いが強い

分類器が消費する追加トークンは、Pro / Max / Team では課金しない扱いへ変わった。既定化の対象は**新規セッション**で、自分で設定した既定はそのまま残り、一度だけ切り替えを促すプロンプトが出る。組織が管理設定で固定した既定は変更されない。切り替えは CLI で Shift+Tab、管理側は managed settings の `defaultMode` で全社の既定を固定でき、`disableAutoMode` で無効化もできる。Enterprise・API・Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry では当面 opt-in のままだが、Anthropic は1カ月以内に既定化する方針を示している。

統制を残す側の設計も告知と同時に整理された。分類器はプロジェクト設定（`.claude/settings.json` / `.claude/settings.local.json`）の `autoMode` を**読まない**。チェックインされたリポジトリやビルド手順が自前の許可規則を注入できてしまうためで、組織向けの信頼設定は managed settings 側に置く必要がある。`permissions.deny` は分類器より前に評価され分類器でも上書きできない一方、`permissions.ask` は「押し戻したい操作だけ人の承認へ戻す」用途に使える（`Bash(git push *)` 等）。v2.1.211 以降は**作業中リポジトリの既定ブランチへの push も既定で許可**になっており、以前の「保護ブランチは既定で止まる」前提は既に外れている。

⚠️ **逆向きの材料が1件ある。** AI Now Institute が 7/8 に公開した PoC「Friendly Fire」は、**素の auto-mode（Codex は auto-review）構成そのもの**を対象とする。第三者ライブラリのドキュメントとソースへプロンプトインジェクションを仕込んでおき、利用者が「このライブラリのセキュリティを見て」と頼むと、エージェントが囮のソースを読んで「このバイナリは安全」と判断し実行してホスト上でコード実行に至る。Hooks・プラグイン・MCP サーバー・設定ファイルをいずれも必要としない。対象は Claude Sonnet 4.6 / Sonnet 5 / Opus 4.8 と GPT-5.5。本リポジトリはこの PoC を未収録で、公開から32日遅れの捕捉になる。

### 2. AMD が Taalas を買収 — 推論単価の下げ方に「モデルを焼いた専用チップ」が加わった

**要点**: AMD が 8/6 に Taalas の買収で合意した。モデルの重みをシリコンへ直接焼き込む方式で、前提は「推論単価は GPU の世代交代とソフト最適化で下がる」から「モデルを固定できるなら専用チップで桁が変わる」へ変わる。

**詳細**: Taalas は2023年設立のトロント拠点。汎用アクセラレータではなく特定モデル向けに設計したチップを作り、推論のデータフローを最適化して計算とメモリの隘路を削る。デモチップ HC1 は Llama 3.1-8B で **1ユーザーあたり毎秒16,960トークン**を記録し、報道は競合 GPU 比で最大48倍としている。自社ツールで設計から完成シリコンまで**約2カ月**で回せるとも説明しており、モデルの更新周期に対して製造周期が追いつくかがこの方式の成否を分ける。**買収金額は非開示**、クロージングは規制当局の承認を条件に **2026年 Q4** の見込み。AMD は Taalas の技術を自社アクセラレータのロードマップへ取り込み、Instinct GPU・EPYC・Helios ラックスケール・ROCm と並ぶシステムレベル製品を作るとしている。07-31 収録の Anthropic × AMD 最大2GW 提携、08-07 収録の Anthropic 自社チップ設計チーム（トークンあたり推論コスト約50%削減を目標）と同じ方向の動きで、推論の原価を下げる打ち手が「単価の値下げ」「消費トークンの削減」に続いて「モデル専用シリコン」へ広がった形になる。⚠️ 一次リリース（`newsroom.amd.com`）はゲートウェイ拒否で本文に到達できず、数値は二次報道の突き合わせで構成した。

### 3. Copilot の impact dashboard に ROI 節が入った — 効果の数値をベンダー側の画面から取れる

**要点**: GitHub が 8/7 に Copilot impact dashboard へ「Potential return on investment」節を追加した。前提は「Copilot の効果は利用率とアンケートで語る」から「1人あたり月額コストと PR 数が管理画面に並んで出る」へ変わる。

**詳細**: Enterprise / Organization の両階層で提供され、開発者を2群に分けて比較するカード形式で表示する。

  - Cost/dev/month: AI クレジットの実消費に基づく、開発者1人あたりの Copilot 月額費用
  - % Payroll/month: その費用を開発者の人件費に対する比率で表したもの
  - Pull requests/month: 開発者1人あたりの月間 PR 数

給与セレクタで報酬帯を切り替えると各指標が即座に再計算される。閲覧できるのは Enterprise owner / billing manager、Organization owner、および「View Copilot Metrics」権限を持つカスタムロールで、Copilot usage metrics ポリシーの有効化が前提になる。⚠️ **GitHub 自身が「費用は AI クレジット消費からの推計、給与セレクタは実際の給与データではなくモデリング入力」と明記**しており、提案書へ引用するなら方向性の指標として扱い、金額の断定には使わない。同日の Changelog では Copilot usage metrics API が**エージェントアプリ別の稼働**を返すようになり（`totals_by_3rd_party_agent` 配列を新設・enterprise / organization の1日および28日レポート対応）、Copilot code review の効力段階 Lite / Balanced が GA になった（組織既定を設定しつつ個別 PR で上書き可・Copilot Enterprise 対象）。07-30 収録の「M365 Copilot 有料シート3,000万超」がシート数の根拠だったのに対し、こちらは定着後の効果側を扱う数字になる。
