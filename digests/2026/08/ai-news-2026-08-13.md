### 1. Claude Code のセルフホスト環境が public beta — コードは自社に残り会話は Anthropic へ行く

**要点**: クラウドセッションを自社インフラで実行できるようになった。統制の前提が「自社ホストなら全部内部で完結する」から「成果物は内部・会話とトランスクリプトは外部」へ変わる。

**詳細**: 8/6 告知で、本日ドキュメントの一次確認により条件が確定した。対象は Team / Enterprise の public beta で**既定はオフ**、Owner か admin が claude.ai の Cloud environments 管理ページで「Allow self-hosted environments」を有効化する（Claude Code on the web の有効化が前提）。境界の引かれ方は次のとおり。

- 自社に残るもの: リポジトリのチェックアウト・ビルド成果物・シークレット・セッションが作成／変更したファイル
- Anthropic へ送られるもの: プロンプト・応答・ツール結果。**セッションのトランスクリプトは Anthropic 側に保存**され、別の面からセッションを再開できる
- 通信はすべて `api.anthropic.com` への outbound HTTPS で、Anthropic 側から社内への接続は発生しない
- 推論は Anthropic API に固定される。Amazon Bedrock・Google Cloud Agent Platform・Microsoft Foundry・LLM ゲートウェイ経由へは回せない
- **ZDR（Zero Data Retention）有効組織は利用できない**

runner は最初のセッションを取った時点でそのユーザーのアカウントへロックされ、チェックアウトしたコードが利用者間で混ざらない。約60秒ポーリングが途切れるとセッションは別 runner へ再投入される。運用形態は固定台数と、キューに応じて runner を起動・終了するオーケストレータ方式の2つ。対応面は Claude Code on the web・モバイル／デスクトップアプリ・スケジュール実行（routines）・`claude --cloud` で、Claude Tag・Claude Security・Code Review は未対応。リポジトリは GitHub からのチェックアウトのみ、課金は Anthropic ホスト環境と同じ扱い。08-08 収録の 2.1.225 の `claude self-hosted-runner` コマンドを製品として組み上げたもので、告知を**7日遅れ**で捕捉した。

- https://claude.com/blog/run-claude-code-sessions-on-your-own-compute
- https://code.claude.com/docs/en/self-hosted-environments

### 2. Agent Plugins 1.0 が Copilot 全面で GA — 管理者側に3つの統制点が付いた

**要点**: GitHub が VS Code・CLI・アプリ・SDK の全面で GA にし全サブスクリプションを対象にした。プラグイン統制の前提が「クライアントごとに個別」から「`managed-settings.json` で組織一括」へ変わる。

**詳細**: 8/12 の Changelog。08-08 収録の Agent Plugins 1.0.0 仕様公開（8/6）に対し、提唱側の GitHub が自社クライアントを揃えた。標準化される構成要素は3種。

- skills: プラグインに同梱するエージェント能力
- MCP サーバー: ツール統合とその設定
- Copilot 固有機能: カスタムエージェント・コマンド・ルール・フック・拡張。可搬性のため `com.github.copilot/` 名前空間に格納する

既定のカタログは **Awesome Copilot marketplace** で、VS Code・Copilot CLI・Copilot アプリで既定有効。Business / Enterprise の管理者は `managed-settings.json` から `enabledPlugins`（特定プラグインの自動導入とブロック）・`extraKnownMarketplaces`（参照先マーケットプレイスの追加）・`strictKnownMarketplaces`（承認済みソースへ導入を限定）の3つを設定できる。MCP 許可リストは URL・コマンド・名前の単位でサーバーを承認またはブロックする。08-10 収録の Codex CLI 0.147.0 が同仕様への対応第一弾だったのに対し、本件はクライアント側の実装が一巡した段階にあたる。

- https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app/

### 3. OpenAI Daybreak が Amazon Bedrock で提供開始 — 審査経路は OpenAI 側のまま

**要点**: OpenAI と AWS が 08-12 収録の Daybreak Blue / Red を Bedrock 上で提供し始めた。調達の前提が「OpenAI と直接契約する」から「既存の Bedrock 契約に載せる」へ変わる一方、利用審査は OpenAI 側に残る。

**詳細**: 8/11 提供開始。**Daybreak Blue** は GPT-5.6 Sol を含むフロンティア汎用モデルへ、認可された防御側業務に合わせた安全機構の調整つきで到達する。**Daybreak Red** は認可された脆弱性研究・エクスプロイト検証・セキュリティテスト向けの専用学習モデル **GPT-5.6 Cyber** を扱う。稼働リージョンは US East（バージニア北部）のみ。利用には OpenAI の Trusted Access for Cyber 審査プログラムへの登録が要り、承認後は Bedrock コンソールか Responses API（`bedrock-mantle` エンドポイント）から呼び出す。⚠️ 08-12 収録の「9月1日から Blue / Red の全個人アカウントでハードウェアセキュリティキーが必須」が Bedrock 経由の利用にも掛かるかは、本日時点で明示されていない。
