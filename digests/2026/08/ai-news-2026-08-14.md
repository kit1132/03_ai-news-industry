### 2. Claude Code の auto mode が本日から既定に — Pro / Max / Team

**要点**: 8/7 に告知された切替日が本日 8/14 にあたる。前提が「危険なツール呼び出しは人が都度承認する」から「分類器が既定で判定し、拒否ルールを書いていなければ止まらない」へ変わる。

**詳細**: 対象は Pro / Max / Team。既定モードを変更していない利用者には当日にアプリ内通知が出て、以後セッションが auto mode で始まる。別の既定を設定済みの場合は、切り替えるかどうかを一度だけ聞かれる。分類器は各ツール呼び出しをその場で評価し、破壊的・不可逆・プロジェクト外へ到達する操作と判定されない限り承認なしで進む。Anthropic の対照実験では、仕込んだ危険なコマンドを人間のレビュアーが捕捉したのは **13.6%**、auto mode は **89%** だった。分類器のトークン費用は Pro / Max / Team の利用上限には算入されない。

既定化の範囲は当面この3プランにとどまる。Claude Enterprise・Claude API・AWS 上の Claude Platform・Amazon Bedrock・Google Cloud Agent Platform・Microsoft Foundry ではオプトインのままで、1カ月以内に既定へ移す計画が示されている。⚠️ 08-09 収録の AI Now Institute の PoC「Friendly Fire」は、素の auto mode 構成のまま第三者ライブラリのセキュリティレビューを依頼するとホスト上でのコード実行に至ることを示していた。本日の既定化は、**その構成が Pro / Max / Team の全利用者に既定として広がる**ことを意味する。統制はプロンプトではなく拒否ルールとサンドボックス設定の側で書く必要がある。

### 3. ChatGPT Enterprise / Edu の個人同期が本日停止 — 同期データの削除も始まる

**要点**: 個人が自分で認可した同期コネクタが本日無効化され、紐づく同期済みデータの削除が始まる。前提が「利用者が各自でファイル連携する」から「管理者が同期を設計しないと社内知識が消える」へ変わる。

**詳細**: 対象は ChatGPT Enterprise / Edu の connected apps。8月10日から個人が新規に認可する同期接続を作れなくなり、**8月14日に既存の個人同期接続が無効化**され、あわせて同期済みデータの削除が始まる。管理者が管理する同期（admin-managed sync）は影響を受けない。管理者側に求められる対応は次のとおり。

- Google Drive: プラグインを有効化する。同期済みナレッジが必要な場合は **domain-wide delegation** で管理者管理の同期を構成する

連携の設計責任が利用者から管理者へ移るとともに、対応を取らなかったワークスペースでは同期済みナレッジが失われる。08-13 までのダイジェストに本件の記載はなく、実施当日での捕捉になった。⚠️ 一次の `help.openai.com` はオリジン403（`curl` HTTP 403）で本文に到達できず、リリースノートを引く二次スニペットの突き合わせで構成した（B-005 準拠）。
