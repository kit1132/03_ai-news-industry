### 1. JetBrains が Fable 5 を自社モノレポで評価・配備 — Python 合格率 44.3%（Opus 4.8 は 28.2%）

**要点**: 公開ベンチではなく自社の非公開リポジトリで測った合格率が16ポイント上がり、解決までの手数も約22%減った。モデル選定の根拠を「公開ベンチの順位」から「自社リポでの合格率とタスクあたり費用」へ置き換えられる、定量値つきの事例が出た。

**詳細**: 8/13 に `claude.com/blog` へ掲載された記事を本日はじめて本文取得した（08-15 は一覧に題名を確認しながら本文 URL を特定できず未確認で残していた）。CTO の Vladislav Tankov によると、JetBrains はモノレポを含む非公開リポジトリ上に大規模な評価セットを維持し、**品質・タスクあたり費用・速度**の3軸で社内リーダーボードを回している。公開ベンチで高得点を取ることではなく実務で動くかを見る設計にしている。Fable 5 の Python 合格率は **44.3%** で Opus 4.8 の **28.2%** を16ポイント上回り、直接比較では Opus 4.8 が失敗した18タスクを解いて落としたのは2タスクだった。working solution へ到達するまでの手数は Opus 4.8 比で約22%少ない。配備先は複雑な推論を要する協働作業、IDE コンポーネント実装の長時間エージェント実行、自社製品に対するホワイトボックスの脆弱性検査、フレームワーク移行と言語間のコード変換。統制はモデル側を改変せず「モデルの周囲にインフラと安全網を作る」方針で、データ保持については重大事例の調査に限定したレビューであれば許容するとしている。Fable 5 は 6/9 に一般提供が始まった Mythos クラスの初モデルにあたる。

### 2. Claude Code 2.1.233 が auto mode の回帰を修正 — 既定化と同じ 8/14 に出た

**要点**: 2.1.232 には通常の Bash コマンドでも手動承認を求め続ける回帰が入っており、auto mode が Pro / Max / Team の既定になった当日に修正版が出た。8/14 以降に「承認が減らない」と観測した場合、設定ではなくバージョンを先に疑う前提に変わる。

**詳細**: 8/14 リリース。08-15 収録の 2.1.232（8/13・`/fork` の意味変更を含む破壊的変更）の翌日ぶんで、本リポジトリは2日遅れの捕捉になった。統制と費用配賦に効く追加は3件で、いずれもオプトインまたは環境変数による設定。

- `forward_user_identity`: apps gateway のオプトイン設定。支出を利用者単位で帰属できる
- `CLAUDE_CODE_TOOL_MEMORY_LIMIT`: Linux で Bash ツールの実行に memory cgroup を掛けられる
- `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`: WebFetch のセッション URL キャッシュ TTL を設定できる

挙動側では、タスク管理ツール（TaskCreate / TaskGet / TaskUpdate / TaskList と TodoWrite）が新しいモデルでは**既定で無効**になり、戻すには `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` が要る。ほかに GitLab のマージリクエスト URL を `--worktree` フラグと `claude agents` ビューが扱えるようになり（`!N` 形式で表示）、権限プロンプト中にクラウドセッションが lost 扱いになる問題・MCP v2 接続がサブスクリプションを際限なく開き直す問題・Windows のパス検証とサンドボックスの各種問題を修正した。`claude self-hosted-runner` のセッション起動が高速化し、apps gateway の Vertex / Foundry / AWS 上流に対するエラー転送も改善している。

- https://code.claude.com/docs/en/changelog

## AI セキュリティ・プライバシー

- **Google が FHE コンパイラ HEIR を公開した — 暗号化したまま推論する経路。** 8/15 に自社の Private Computing Toolkit の一部として公表した。完全準同型暗号（FHE）向けの MLIR ベースのコンパイラツールチェーンで、学習済みモデルを FHE 対応の形へ自動変換し、復号せずに暗号化された入力のまま推論を走らせる。想定用途はレコメンドや不正検知で、これまで暗号研究者の専門知識を要した FHE の導入障壁を下げる位置づけになる。対応スキームとバックエンドは、OpenFHE と Lattigo が BGV / BFV / CKKS、tfhe-rs と Jaxite が CGGI。ライセンスは **Apache 2.0**。⚠️ リポジトリには「これは Google の公式サポート製品ではない」と明記されており、**提案に載せる場合は本番運用の前提として書かない**。一次告知の `blog.google` はゲートウェイ拒否のため公表日は二次確認による。
