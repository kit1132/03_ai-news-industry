### 1. Copilot が 8/18 に3機能を廃止 — Group Chat は履歴ごと消える

**要点**: 8/18 開始。Copilot アプリ統合にあわせ Group Chat・Podcasts・Deep Research（消費者向け）が廃止され、**Group Chat のスレッドと画像は完全削除**される。本リポジトリは 08-17 に URL 移行だけを記録し、削除を伴う側を見落としていた。

**詳細**: Microsoft は消費者向け Copilot と商用 Copilot を1つの「Microsoft Copilot」アプリへ束ねる移行を 8/18 に開始した。Partner Center の 8/14 付告知（一次）が扱うのは、アカウント判別の視覚指標・アプリ名とアイコンの簡素化・Web URL の `m365.cloud.microsoft` から `copilot.cloud.microsoft` への移行の3点で、**セキュリティ・コンプライアンス・ガバナンスの制御に変更はない**とされる。一方、同じ 8/18 を期日とする機能廃止は告知の外側にあり、二次報道でのみ具体化している。

- Group Chat: スレッドと内部の画像が恒久削除される。退避手段の案内は無い
- Podcasts: 消費者向け Copilot アプリで廃止。ライブラリの音声ファイルは個別ダウンロードでのみ退避できる
- Deep Research: 消費者向けで廃止。**保存済みレポートは 8/18 以降も残る**が新規作成はできない。後継の Researcher は Microsoft 365 Premium の加入者のみ

Windows / Mac デスクトップ版の早期プレビューも 8/18 開始で、広範展開は9月中旬から。プレビュー中はタスクバーの Ask Copilot が一時無効化され、Notebooks・Connectors・Vision が一時的に使えなくなる（Windows Insider リリースノート・version 152.0.4191.25）。⚠️ **廃止対象は「消費者向け Copilot」であって M365 Copilot ではない**が、統合後は同一アプリの中で両者が同居するため、社内の利用者が個人アカウント側で作った Podcasts / Deep Research の成果物は退避の対象になる。

### 2. Copilot Autofix 由来のコードを別の AI が5日で悪用 — 自動修正の出力は無検証で入れられない

**要点**: Wiz の攻撃側エージェントが Snowflake の公開リポジトリでコマンドインジェクションを見つけ、社内 Jira の読み取りまで到達した。「AI の自動修正パッチは安全側に倒れる」という前提が、検証工程を挟む前提へ変わる。

**詳細**: 対象は `snowflakedb/snowflake-connector-net` の GitHub Actions ワークフロー。**6/18 に PR #1218 が merge されて脆弱性が生き**、**6/23 に Wiz の Red Agent が公開リポジトリの定期スキャン中に検出**した。存在期間はわずか5日である。攻撃は認証不要で、細工した題名の Issue を立てるだけで Actions ランナー上の任意コマンド実行に至る。Wiz は取得したトークンで `snowflakecomputing.atlassian.net` へ認証し、エンジニアリング・セキュリティコンプライアンス・バグバウンティの各プロジェクトを読み取れる状態を確認した。Snowflake の HackerOne 経由で報告され 6/23 に修正済み。

⚠️ **Copilot の関与について当事者の見解が割れている**（B-005 準拠）。

- Wiz 側: 当該コミットは Copilot Autofix が co-author として入っており、既存のサニタイズ済み入力パターンを削除して `run:` ブロックでのシェル変数展開に置き換えたとする
- GitHub 側: 社内レビューの結果、脆弱性につながった変更は**人間が書いたもので Copilot の関与もレビューもない**と否認している

どちらの主張を採っても、**AI が関与しうるコード変更経路に対して静的解析と人間のレビューを残す**という運用上の結論は変わらない。同型の入口（Issue 題名を `run:` に展開する Actions ワークフロー）は既知の古典的パターンであり、Autofix・エージェント・人間のいずれが書いたかを問わず検出できる。

### 3. Claude Code 2.1.234 が Windows パス偽装とシークレット露出を修正 — 当日から更新対象

**要点**: 8/17 公開。**Windows NT 名前空間パス（`\??\`）の拒否**を主要な入力経路すべてに広げ、MCP 診断が解決済みシークレットを表示していた問題も直した。統制設定を触っている環境は当日から更新の対象になる。

**詳細**: 拒否の対象はリモートファイル読み取り・セッション復元・CLAUDE.md の include・ワークフロースクリプト・ファイルアップロードの5経路。2.1.233（8/14）が UNC パス検証の迂回として NTLM 資格情報漏洩の経路を1件塞いだのに続く、同系統の拡張にあたる。ほかの統制系は次の3件。

- MCP 診断がスコープ衝突の警告で解決済みシークレットを印字していた問題を修正し、`${VAR}` 形式で表示するようにした
- `strictKnownMarketplaces` がホスト不一致の SCP 形式 git ソースを受理していた問題を修正した
- チャネルサーバーへ中継される権限プレビューが尊重されるようになった

機能面では、使用量上限のリセット時にセッションを自動継続する挙動（`/config` で設定可）、`/add-dir` の後に発火する `DirectoryAdded` フック、プロジェクト別のトランスクリプト用ディレクトリを指定する `CLAUDE_CODE_PROJECT_DIR_NAME`、GitLab マージリクエストのバッジ表示が入った。長時間セッションで auto mode がサンドボックス済みコマンドのネットワーク到達性を繰り返し再確認する問題も直っている。
