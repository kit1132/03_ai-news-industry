### 1. Claude API の Computer Use と Files API・Agent Skills が同日に GA — beta ヘッダー前提の実装を書き直す判断日

**要点**: 8/19 に Claude API 側で GA 4本立て（Computer Use / Files API / Agent Skills / Enterprise 利用者管理）と新規1本（Browser Use）。**`anthropic-beta` ヘッダーの送信が不要になり、送っても従来動作**という互換設計だが、Computer Use は toolset 名が `computer_toolset_20260801` に変わりリクエスト形状も変わる。既存のエージェント実装は「beta 前提で書いた分岐」を GA 前提に整理するか判断できる材料が揃った。

**詳細**: 前日 08-20 のダイジェストは同日の Enterprise Admin API GA のみ扱っており、**残り4本（Computer Use / Browser Use / Files API / Agent Skills）は本リポジトリで未収録**だった。個別の内容は次のとおり。

- **Computer Use GA**: 新 toolset 名 `computer_toolset_20260801` として一般提供。beta ヘッダー不要・**バッチ操作**（1ターンで複数アクション）・`zoom` を既定で有効・`configs` によるメンバー別設定に対応。旧 beta 版は継続利用可。既存統合の移行手順は `computer_20251124` からの migration ガイドに集約。対応モデルは Claude Fable 5 / Mythos 5 / Opus 5 / Sonnet 5 / Opus 4.8
- **Browser Use tool 新設**: `browser_toolset_20260801` として同日新規公開。**デスクトップ全体ではなくブラウザビューポート内で動く**クライアント側 toolset で、ページのアクセシビリティツリー・要素・フォーム・タブを読み取り、要素参照・フォーム入力・タブ管理・ダウンロード報告・（オプトインの）ファイルアップロードを screenshot-and-click 制御の上に載せる。対応モデルは Computer Use と同じ5系統
- **Files API GA**: `/v1/files` エンドポイントと Messages API のファイル参照要求で `files-api-2025-04-14` ヘッダーが不要に。GA 応答形式では**アップロード時に `expires_in_seconds` を設定でき**、ファイルオブジェクトに `expires_at` が入る。一覧取得に `page` / `next_page` ページングと `ids[]` フィルタが追加。beta ヘッダーを送るリクエストは旧応答形式のまま動作
- **Agent Skills GA**: `/v1/skills` エンドポイントと、Messages API の `container` 経由の Skills 読み込みで `skills-2025-10-02` ヘッダーが不要に。beta ヘッダー付き要求はそのまま動作
- **Enterprise Admin API GA**（08-20 に既収録）: 利用者管理エンドポイントで `anthropic-beta: ce-user-management-2026-07-13` が不要に

⚠️ **本リポジトリは「昨日の一次リリースノートの中身を今日はじめて拾い直した」形になる。** 08-20 のダイジェストは同じ `platform.claude.com/docs/en/release-notes/api` を出典に引きながら Admin API GA のみを収録し、同ページに並ぶ Computer Use・Browser Use・Files API・Agent Skills を落とした。B-008（週次スイープ）と B-027（記録済み期限の再確認）に加え、**「今日のリリースノートの当日エントリを1本ずつ通読する」手順の欠落**が別の欠落として顕在化した。8/19 の該当ページには本エントリ以外にも Managed Agents の `web_search` / `web_fetch` の許可・拒否ドメイン制御、self-hosted サンドボックスへのメモリストア接続、Console のセッション viewer 刷新が並んでいる（下記「エンタープライズ・統制」参照）。

### 2. Claude Managed Agents の Web ツールに許可・拒否ドメイン設定が入った — エージェントの Web 到達範囲が組織ポリシーの対象になった

**要点**: 8/19 公開。Managed Agents の `web_search` と `web_fetch` に**接続先ホワイトリスト／ブラックリスト**を掛けられるようになった。`web_fetch` は取得量の上限（`max_content_tokens`）、`web_search` は検索地域（`user_location`）も別軸で指定可能。エージェント経由の外部到達を IT が握れる。

**詳細**: `agent_toolset_20260401` の `configs` 配列に載せる各エントリで、`allowed_domains` または `blocked_domains` を設定する。`configs` のエントリは `name` で識別し、任意の `type` で分類する。**従来どおり `name` / `enabled` / `permission_policy` だけを渡す形も継続して動く**ため、既存の agent 定義を触らずに新機能だけを足せる。TypeScript / Python 等の型付き SDK では `configs` エントリがツール別型に落ちる。⚠️ 上限値・**同一エージェント内で `web_search` と `web_fetch` に別々のリストを付けられるのか、`permission_policy` との優先順位**は告知に明記が無く、実装時に確認する必要が残る。08-20 収録の Copilot for JetBrains の `allowedMcpServers` / `deniedMcpServers` と同じ「外部到達を組織で束ねる」統制語彙で、モデルベンダー・IDE ベンダーの双方が同時に同じ形へ寄せた形になる。

- https://platform.claude.com/docs/en/managed-agents/tools#restrict-web-search-and-web-fetch-domains
- https://platform.claude.com/docs/en/release-notes/api
