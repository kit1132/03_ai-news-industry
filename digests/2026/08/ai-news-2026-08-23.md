### 1. Claude Code 2.1.239 が課金のズレを2つ塞いだ — 見積もりの前提が実額へ戻る

**要点**: 表示される費用が実額とずれる原因が2つ同時に消えた。US 固定推論の 1.1倍割増が `/cost` に反映され、Bedrock 経由で課金 API 呼び出しが黙って2倍になる不具合が直った。試算の前提が「表示値≒実額」へ戻る。

**詳細**: 8/21 公開の 2.1.239 と 8/22 の 2.1.240（後者は不具合修正のみ）。変更は2系統ある。

- 費用表示: `/cost`・ステータスライン・`--max-budget-usd` が、データレジデンシー設定のワークスペースに掛かる **1.1倍の US 限定推論割増**を含めて計算するようになった。一次ドキュメントによると `inference_geo: "us"` は Claude 4.6 以降で入力・出力・キャッシュ書き込み・キャッシュ読み出しの**全区分に 1.1倍**が掛かり、Priority Tier では1トークンが 1.1トークンとして枠を消費する。ワークスペース geo は作成後に変更できず現状 `"us"` のみで、旧「グローバルルーティング opt-out」の組織は `allowed_inference_geos: ["us"]` へ自動移行済み
- 二重課金: レスポンスの `Content-Type` ヘッダーを落とすプロキシの背後で Bedrock のストリーミングが失敗し、**毎ターン非ストリーミングで再実行されて課金対象の API 呼び出しが2倍**になっていた不具合を修正した。あわせて Bedrock ＋ SSO プロファイル ＋ `awsAuthRefresh` の構成が HTTPS プロキシ下で起動時にハングする問題も、資格情報の事前チェックが `HTTPS_PROXY` を尊重する形で直っている
- 移行支援: `/claude-api upgrade` が追加され、Python プロジェクトを `anthropic` 0.x から 1.x へ移行できる。08-22 収録の Python SDK v1.0（`httpx` → `httpx2`・Python 3.10 以上・サンプリング系パラメータ削除）に対応する導線にあたる

出典:
- https://code.claude.com/docs/en/changelog
- https://platform.claude.com/docs/en/manage-claude/data-residency

### 2. Claude の本番エージェント3 API が出揃った — 導入側の定量値が初めて付いた

**要点**: Anthropic が 8/19 GA の Computer Use / Skills / Files API を本番エージェントの構成として束ね、導入側 Asteroid の**処理時間 32分→13分・コスト約30%減・完了率100%** を公表した。エージェント提案の効果見積もりを一次の定量値で置ける。

**詳細**: 8/20 公開。08-21 収録のリリースノート（GA 4件＋Browser Use 新設）に対する製品側の解説で、運用条件と定量値が加わった。

- Files API: 組織あたり**ストレージ 1TB**、レート上限は従来比 **5倍**、ファイルの自動失効あり。一度アップロードすれば ID 参照で再利用する
- Computer Use: 1回の呼び出しで**複数操作を1ターンにまとめられる**ようになり往復が減った。BAA の下で HIPAA 適格
- Browser Use: スクリーンショットに加えてページ構造を読み、ピクセル座標ではなく**要素を指定して操作**する。同じく複数操作の1ターン化に対応
- Skills API: 手順書・スクリプト・テンプレートを束ねたフォルダを Claude のコードサンドボックスで実行するため**ホスティングが不要**で、バージョンを付けてリクエストに添付できる
- 提供面: Skills API と Files API は **Microsoft Foundry** でも利用でき、Google Cloud の Vertex AI は近日対応とされる
- 導入事例の Asteroid（医療・保険金請求）は、プロンプトを変えずに処理時間 32分→13分、検証したワークフロー全体でコスト約30%減、完了率100% を報告している

出典:
- https://claude.com/blog/computer-use-skills-api-files-api
- https://platform.claude.com/docs/en/release-notes/api

## エンタープライズ・エージェント基盤

- **Pinecone Nexus が GA になった — 知識層がフロンティアモデルの差を上回るという主張。** 企業の独自データとワークフローを統制付きの知識層へコンパイルし、エージェントが**1回の呼び出しで参照**する構成にする。都度 raw ドキュメントから文脈を組み立てる RAG パイプラインの置き換えを狙う。Sierra の公開ベンチ **τ-Knowledge** で、Nexus を知識層に据えたエージェントが OpenAI / Anthropic / Google のフロンティアモデルで組んだエージェントを上回り首位になったとする。デプロイは顧客自身の AWS / Google Cloud / Azure 環境内で、オープンウェイトを含む任意のモデルを使え、Pinecone 側に常時のデータアクセスは生じない。対象を金融アナリスト・引受担当・弁護士・カスタマーサービスといった事業部門の実務者へ広げている。⚠️ **GA の日付が二次で割れている**（8月6日とする集計と、プレスリリース配信・報道が 8月18〜19日とする系統）。一次の `www.pinecone.io` と配信元 `www.prnewswire.com` がいずれもゲートウェイ拒否で確定できず、**ベンチ結果もベンダー自己申告で第三者検証値はない**（出典: https://www.pinecone.io/blog/pinecone-nexus-generally-available/ ・到達不可のため WebSearch のスニペットで構成）
