### 1. Assistants API と ChatGPT の o3 が本日停止 — 移行猶予が今日で切れる

**要点**: OpenAI の Assistants API と ChatGPT の o3 が本日 8/26 に停止する。撤回・延期がないことを一次で最終確認した。エージェント実装の前提が Assistants から Responses + Conversations へ確定した。

**詳細**: 08-24 に初収録し 08-25 に期限1日前の再確認を行った期限が、本日到来した。一次ドキュメントの記載は前日から変わらず、告知は 2025年8月26日で12カ月の予告期間を経ている。

- API 側: `/v1/assistants` `/v1/threads` `/v1/threads/runs` が縮退運転も猶予期間もなくエラーを返す。Threads → Conversations の自動移行ツールは提供されない
- 代替: Responses API と Conversations API の組み合わせ。deep research・MCP・computer use は Responses 側に乗る
- ChatGPT 側: o3 が web とモバイルのモデルピッカーから外れる。90日のサンセット期間を経ての除去で、既存の o3 会話は対応する GPT-5 系へ引き継がれる。推奨代替は GPT-5.4 Thinking と o4
- API の o3 は対象外で、`o3-2025-04-16` と `o3-pro-2025-06-10` の停止は **12月11日**（代替はいずれも GPT-5.6 Sol、pro は `reasoning.mode: pro` 付き）

⚠️ 停止が実際に反映されたかは、日本時間の本日午前時点では未確認である。一次ページは「Upcoming deprecations」の区分に本項を置いたままで、反映の確認は 8/27 の収録に回す。同ページの他の期限（9/24 Videos API と Sora 2 系、10/23 と 9/28 の旧 GPT スナップショット、11/30 Evals / Agent Builder / `v1/prompts`、12/1 GPT Image 系、12/11 GPT-5 と o3 のスナップショット、2027/1/20 旧 audio / realtime / transcription 系）はいずれも変更なし。

### 2. OpenAI がファインチューニングを畳む — 2027年1月6日に新規ジョブ作成を全面終了

**要点**: OpenAI がファインチューニングの新規ジョブ作成を 2027年1月6日に全面終了することが一次で判明した。モデル特化の手段が微調整からプロンプト・RAG・エージェント設計へ寄る。

**詳細**: 退役ページの再確認で、これまで本リポジトリが一度も収録していなかった項目が確定した。締切は単日ではなく**3段階で既に2段階が過ぎている**。

- **2026年5月7日**（実施済み）: ファインチューニングを一度も実行したことがない組織は、新規の学習ジョブを作成できない
- **2026年7月2日**（実施済み）: 過去60日以内にファインチューニング済みモデルで推論を実行していない組織は、新規の学習ジョブを作成できない
- **2027年1月6日**: 稼働中の既存顧客も新規のファインチューニングジョブを作成できなくなる

推論側の扱いは別で、**作成済みのファインチューニング済みモデルの推論は、基となるベースモデルが退役するまで動く**。つまり止まるのは「新しく作ること」であって、既存の学習済みモデルが即日使えなくなるわけではない。ただし 10月23日には旧 GPT スナップショットとそのファインチューン版が停止するため、古いベースモデル上の資産から順に効いてくる。OpenAI 側の理由づけは「新しいベースモデルは指示と書式の追従が十分に良くなり、ファインチューニングの多くが不要になった」というもの。

⚠️ ⚠️ 5月7日の告知そのものは本リポジトリの収録外で、**今日はじめて一次ページで全体像を確認した**（発生から約3.5カ月遅れ）。提案上の含意は、OpenAI を前提に「自社データでモデルを微調整する」と書いた構成が、2027年1月以降は新規に作れないという点にある。同種の選択肢を残すなら Anthropic・Google 側の対応状況を別途確認する必要がある。

### 3. Claude Code に組織契約単価の設定が入った — 費用集計が推定から実額へ

**要点**: Claude Code に組織契約単価を反映する `modelPricing` 管理設定とプロンプトキャッシュ TTL の設定が入った。社内展開のコスト根拠が公開単価による推定から実契約額の集計へ変わる。

**詳細**: 8/25 に **2.1.243** が大型更新として公開され、同日 **2.1.245** が追随した。2.1.240〜2.1.241 が "Bug fixes and reliability improvements" のみだったのに対し、統制と費用に関わる設定が複数入っている。

- `modelPricing`: 組織が契約したモデル別単価を管理設定として与える。既定では公開単価で計算されるコスト表示が、契約額ベースに変わる
- `promptCacheTtl` / `subagentPromptCacheTtl`: プロンプトキャッシュの保持時間を設定で制御する。サブエージェント側を別に設定できる
- `modelPicker`: `/model` のピッカーに出すモデルを、順序とラベル付きで組織が絞り込める
- `/usage` に Loops の内訳が加わり、ループ単位の実行回数・総トークン・実行あたりトークン・最終実行が見えるようになった
- Anthropic Console からのキーレスサインインが `/login` に追加された
- 切断したリモート MCP サーバーが再接続しない不具合を修正。`/resume` が直近50件しか出さない制限も撤廃
- 起動時間とバイナリサイズを改善（zstd 圧縮で Linux x64 は 340MB → 約 **75MB**）
- 2.1.245 は glibc 2.44 系ディストリビューション（Arch・CachyOS・Fedora Rawhide）の起動時クラッシュを修正した

`modelPricing` と `modelPicker` はいずれも managed setting で、個人設定ではなく組織側から配布する種類にあたる。⚠️ 単価表の書式・適用範囲（Bedrock / Vertex 経由を含むか）は changelog の記載では確定できない。
