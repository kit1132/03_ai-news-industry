### 1. Claude in Chrome が GA — ブラウザ操作が「都度承認」から自律実行へ

**要点**: Claude in Chrome が全有料プランで GA になり、1操作ごとの承認なしにブラウザを自律操作するようになった。ブラウザ操作エージェントの前提が、人が都度承認する運用から分類器による事前検証へ移った。

**詳細**: 8/26 公開。既存のログイン状態を使って、閲覧中のページの読み取り・文字入力・リンククリック・ページ遷移・フォーム入力を行う拡張機能で、2025年8月のリサーチプレビューから約1年での GA にあたる。

- 動作の変更: 従来は1操作ごとに承認が必要だったが、GA では実行前に安全性分類器が検証する形に変わり、承認なしで一連の操作を続けられる
- 提供範囲: **すべての有料プラン**が対象。Enterprise では管理者が Organization Settings で可否を制御し、**承認済みドメインに限定**できる
- プロンプトインジェクション対策は3層構成で、①攻撃ライブラリを拡張したモデル学習、②ツール結果を走査するプローブ、③実行直前の操作が当初の依頼と整合するかを照合する分類器を組み合わせる
- 対策込みの攻撃成功率は Claude Opus 5 が **0%**（対策前 3.8%）、Claude Sonnet 5 が 0%、Claude Fable 5 が 0.3%

⚠️ 数値はいずれも Anthropic 自身のレッドチーム評価であり、第三者検証ではない。組織展開の観点では、承認済みドメインの限定をかけずに配布すると、社内 SaaS の画面をエージェントが自律操作できる状態になる点が確認事項になる。08-12 に収録した Cowork のサイドパネル化（セッション連続性）とは別の変更で、そちらは会話の器、本件は操作の権限にあたる。

### 2. Compliance API のセッション取得が GA — Claude の利用ログが監査対象になった

**要点**: Cowork と Claude Code のセッション全文を取得する Compliance API がベータを抜け、Claude Science と M365 Office エージェントの記録も対象に加わった。利用ログが「取れるかもしれない」から監査運用の対象へ変わった。

**詳細**: 8/26 のプラットフォームリリースノートで確認した。08-11 にベータ提供が始まった機能で、2週間強での GA になる。

- GA になった範囲: 利用者の端末で動く **Cowork と Claude Code** のセッション取得エンドポイント。組織横断の一覧・個別セッションのメタデータ・トランスクリプトの3系統
- ベータで追加された範囲: Claude Science セッション（`product_surface` が `claude_science`）と、Excel・PowerPoint・Word・Outlook 上の Claude for Microsoft 365 セッション（`office_agents` で始まる値）。対象は Claude Enterprise 組織
- 必要な資格情報は既存の Compliance Access Key と `read:compliance_user_data` スコープで、追加の申請はいらない
- 同日、**Admin API が `ant` CLI と7言語 SDK**（Python・TypeScript・C#・Go・Java・PHP・Ruby）の `client.beta.organization` に載った。組織情報・メンバー・招待・ワークスペース・API キー・レート制限・サービスアカウント・ワークロード ID フェデレーション・顧客管理鍵を扱える
- ⚠️ 利用量とコストのレポート、および Claude Enterprise のユーザー管理・分析エンドポイントは **curl 専用のまま**で、SDK からは呼べない

情シス側の含意は、Claude の社内展開でこれまで「端末上のセッションは追えない」を前提に置いていた設計が組み直せる点にある。M365 の Office アプリ内エージェントまで同じ鍵で追えるため、Copilot との併存環境でログ収集の窓口を1つにまとめられる。

### 3. A2A が Linux Foundation 傘下へ — MCP と同じ屋根の下に入った

**要点**: Google の A2A が Linux Foundation 傘下の Agentic AI Foundation へ移管され、Anthropic 由来の MCP と同じ中立組織の管理下に入った。エージェント間連携の標準が単一ベンダー保有から共通基盤へ変わった。

**詳細**: 8月17日の Axios 報道を皮切りに、8月19〜20日にかけて移管が公表された。本リポジトリでは本日はじめて確認した項目で、発生から7〜10日遅れの捕捉にあたる。

- 役割の分担: **MCP** はエージェントとツールの縦方向（データベース・API・ファイルシステムへの到達）、**A2A** はエージェント同士の横方向（依頼と結果の受け渡し）を標準化する
- A2A の仕組みは、各エージェントが能力と到達方法を記述した agent card を公開し、他のエージェントがそれを読んで人の仲介なしに作業を引き渡すというもの
- 経緯は Google が 2025年4月に公開し、**2026年3月に v1.0** へ到達、採用組織は150超に及ぶ
- AAIF は発足1年足らずで加盟が **49社から250社超**へ増え、Platinum には AWS・Anthropic・Block・Bloomberg・Cloudflare・Google・Microsoft・OpenAI が名を連ねる

提案上の含意は、マルチエージェント構成の設計で A2A を採る際に「Google 独自プロトコルへの依存」という論点が消えることにある。MCP と A2A が同一財団の下に揃ったため、ツール接続とエージェント間連携を別々のガバナンス前提で説明する必要がなくなる。⚠️ 一次の `www.linuxfoundation.org` はゲートウェイ拒否で本文に到達できず、公表日が **8/17・8/19・8/20** の3系統に割れているため、日付を単日で引用しないこと。

## AI業界動向・エージェント統制

- **OpenAI が ZDR を保ったまま悪用検知する方式を予告した** — OpenAI が 8月19日に Private Safety Processing を公表した。ゼロデータ保持（ZDR）の対象顧客に対して、複数の関連するやり取りをまたいだ悪用パターンを検出しつつ、プロンプトと応答を同社の担当者が閲覧しない構成をとる。ZDR 側の約束は、リクエスト処理後にプロンプトと応答を保持しないこと、顧客コンテンツを同社の担当者のレビュー対象にしないこと、明示的なオプトイン無しに学習へ使わないことの3点である。保管の選択肢として、顧客が管理するインフラに置く方式に加え、**顧客が管理する鍵で暗号化した OpenAI ホスト型**を開発中とする。⚠️ 現時点では preview の位置づけで一般提供時期は示されていない。エンタープライズ提案でこれまで「ZDR を選ぶと悪用監視が単一リクエスト単位に限られる」と説明していた前提が動く可能性がある項目で、動向を追う対象にあたる。https://openai.com/index/offering-zero-data-retention-for-frontier-models/
