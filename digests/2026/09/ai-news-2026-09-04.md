### 2. Anthropic が ZDR と Fable 5.1 の両立策を出した — 「年内の個別申請」から恒久策へ変わった

**要点**: Anthropic が9月2日に Enterprise Frontier Safeguards を公表した。監視ログを顧客自身の S3 / Azure Blob / GCS に顧客の鍵で置く方式で、「Fable 5.1 は ZDR 契約下では使えない」という 09-02・09-03 の前提が恒久策の側へ動いた。

**詳細**:

- EFS は zero data retention の秘匿性と不正利用検知を両立させる仕組みで、**監視に使う活動データを Anthropic ではなく顧客が管理するクラウドに置く**。格納先は Amazon S3・Azure Blob Storage・Google Cloud Storage から選び、顧客自身の暗号鍵・アクセスポリシー・監査ログの下に入る
- 検知対象は自動処理がトラフィックのローリングウィンドウを解析する形で、**攻撃的なサイバー能力または生物学的能力の構築の試み**と、**盗まれた／漏洩した認証情報の兆候**の2種類に絞られる
- 提供は今秋以降の段階的ロールアウトで、⚠️ **移行期間中は適格顧客に Fable 5 / Fable 5.1 の ZDR が提供される**。09-03 収録の「zero data retention は年内に限り適格企業が個別申請可」という Copilot 側の記載は、この移行措置と地続きである
- 開発は金融・ヘルスケア・製造・通信・法務・小売・公共の100社超の顧客と、AWS / Google Cloud / Microsoft Azure のクラウドパートナーとの協業による
- 顧客クラウドに置く選択をした場合、**ストレージ・読み書き・データ egress の費用は顧客のクラウド事業者から請求される**。機能自体は任意で、モデルの挙動と単価は変わらない
- ⚠️ **一次本文には到達できていない**。`www.anthropic.com` はゲートウェイ拒否が続き、`claude.com/news/` `claude.com/blog/` の同スラッグはいずれも404だった。内容は複数の二次スニペットの突き合わせによる。**2日遅れの捕捉**である
