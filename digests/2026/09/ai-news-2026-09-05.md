### 1. gh コマンドの Linux 署名鍵が本日失効 — 4月8日より前に入れた環境は今日中に手を入れる

**要点**: GitHub が `gh` の Linux パッケージ署名鍵を本日9月5日に失効させる。2026年4月8日より前に APT / RPM で導入した環境は、鍵を更新しないと以後の取得が検証エラーで止まる。

**詳細**:

- 失効するのは GitHub CLI の Linux パッケージリポジトリ用 PGP 鍵で、期日は **2026年9月5日**。以後、APT / RPM のリポジトリメタデータと新規公開の RPM パッケージは差し替え鍵のみで署名される
- 対象は APT リポジトリ（Debian / Ubuntu 系）と RPM リポジトリ（Red Hat / Fedora 系）の2経路である
- 影響を受けないのは次の導入方法で、一次告知が明示している
  - Windows / macOS を使っている場合
  - ソースからビルドしている場合
  - Homebrew・Conda・コミュニティ製パッケージマネージャー経由
  - GitHub Releases の `.deb` 直取得または単体バイナリ
- 差し替え鍵を含むキーリングは **2026年4月8日**に公開済みで、それ以降に導入・更新した環境は対応済みである。⚠️ **手当てが要るのは、それより前に入れて以来キーリング設定を触っていない環境に限られる**。手順は一次告知および GitHub CLI issue #13118 に記載がある
- ⚠️ 本リポジトリの定点である GitHub Changelog では **Retired** 区分の告知で、9月3日に出て**期日まで2日**しかなかった。CI ランナーやコンテナイメージで `gh` を APT 経由で入れている場合、失効後の初回 `apt update` で初めて表面化する

### 3. Claude Code 2.1.260 が権限まわりを差し戻した — 2版で前提が揺れている

**要点**: Claude Code 2.1.260 が9月3日に出た。2.1.259 で入った Bash 引数への `Read()` 拒否ルール適用が差し戻され、zsh の変数代入に隠したコマンド置換が自動承認される穴も塞がれた。

**詳細**:

- ⚠️ **差し戻しが1件ある。** 「Bash の `Read()` 拒否ルールをオプション値のファイルにも適用する」という 2.1.259 の変更が 2.1.260 で撤回された。09-04 収録時点ではこれを統制の強化として記録していたが、**2版で前提が反転している**
- 権限・サンドボックスの修正が4件並ぶ
  - 括弧を含むパスの `Edit` / `Write` / `Read` 権限ルールが無効扱いで捨てられ、Bash サンドボックスからも無視されていた不具合を修正
  - コンパイルできないパターンのファイル権限ルールが1件あると、**全ファイル編集が `Invalid regular expression` で失敗**していた不具合を修正
  - Bash の権限チェックが `REPORTTIME`・`REPORTMEMORY`・`DIRSTACKSIZE` への代入にコマンド置換を隠した zsh コマンドを自動承認していた不具合を修正
  - `permissions.blockReadsOutsideWorkingDirectories` が macOS でサンドボックス下の git からユーザーの git 設定を隠していた不具合を修正
- 統制面の変更としては、`!` の bash モードで打ったコマンドが**サンドボックス外で実行される**ようになり、閉じ括弧の後ろに文字が続く権限ルールは無効な設定として報告されるようになった。管理下 CLAUDE.md がセキュリティ承認ダイアログを出さなくなる変更も入っている
- 認証・統制の不具合修正も複数入った。claude.ai Enterprise / Team ユーザーに API キーが残っていると管理設定が読み込まれない不具合、`/status` がサインイン済みアカウントと API キーの両方を有効であるかのように表示する不具合、管理下 `skillOverrides` がバンドル済みスキルのエイリアス指定で効かない不具合が対象である
- 機能面では `/diff` でフルスクリーン時に未コミット差分を横に出すパネル、`/cost` とステータスラインの `prompt_cache` へのキャッシュミス原因表示、ヘッドレスセッション向けの `/reload-plugins` と文字列版 `/advisor` が加わった
- ⚠️ **スケジュール実行環境の不具合修正が3版連続で続いている。** 2.1.258 は「remote / scheduled セッションが `user messages must have non-empty content` で失敗」、2.1.259 は「コネクタツールの権限承認後に応答しない」、2.1.260 は「クラウド上の claude.ai セッションで Claude in Chrome が `Not connected` になる」を修正した
