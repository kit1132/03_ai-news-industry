### 1. Microsoft が Release Wave を廃止 — Power Platform の導入計画を半期単位で組む前提が消えた

**要点**: Microsoft が Dynamics 365 / Power Platform / Dataverse の半期リリースウェーブを廃止する。2026 Release Wave 2 の告知は行われず、Release Planner も11月15日に閉じるため、ウェーブ単位の導入計画は組み直しになる。

  - **2026 Release Wave 2 の告知は行われない**。半期ごとの release wave 1 / wave 2 という公表単位そのものを廃止し、計画が固まった時点で随時公開する方式に移る
  - **Release Planner は 2026年11月15日に retire する**。Microsoft Learn 上の Release Plans はアーカイブされる
  - 2026年9月以降、新規のロードマップ項目は **AI at Work roadmap**（`aka.ms/AIatWorkRoadmap`）へ直接公開される。Microsoft 365・Copilot・エージェント・Business Applications のロードマップが1か所に統合される
  - public preview / GA 日付が **2026年6月1日以降**の既存ロードマップ項目は、9月以降に新ロードマップへ移行される見込みとされる
- 影響範囲は**ロードマップ告知に限られる**と一次は明記している。製品のリリーススケジュール・展開プロセス・Message Center 通知・製品ドキュメントは変更されない
- ロードマップデータは **Microsoft Release Communications MCP Server** から無償・サインイン不要で取得できるとされ、CSV エクスポートと RSS 購読も案内されている
- ⚠️ 提案書で「次期 Release Wave で対応予定」という書き方をしている場合、11月15日以降は参照先の URL ごと失われる。⚠️ 本リポジトリの姉妹ソース（02 Copilot）が Release Plan の緑チェックを一次シグナルとして使っている場合、**その計測手段が11月15日で止まる**

### 2. GPT-6 Astra が Copilot で GA — 既定オンかつ従量課金なので、切らない限り単価が上振れする

**要点**: GitHub が GPT-6 Astra を Copilot で一般提供にした。管理者が既定を切っていなければ自動で有効になり、課金はプロバイダー定価の従量制のため、Copilot の費用を premium request 換算で見積もる前提が崩れる。

**詳細**:

- 9月4日告知。対象プランは Copilot **Pro+ / Max / Business / Enterprise** で、⚠️ **Pro は対象外**である（09-04 収録の Gemini 3.8 Flash は Pro を含んでいた）
- 利用面は VS Code・Visual Studio・Copilot CLI・coding agent・Copilot アプリ・github.com・GitHub Mobile（iOS / Android）・JetBrains IDE・Xcode・Eclipse に及ぶ
- 課金は **provider list pricing の従量課金**で、一次告知に premium request の倍率は書かれていない。09-05 収録の OpenAI 一次料金ページの値がそのまま効くと読むと、短文脈で入力 $10／出力 $50、長文脈で $20／$75 になる
- ⚠️ **既定の向きは「自動で有効」である。** 一次は「管理者がグローバル既定を切っているか、このモデルを明示的に無効化していない限り、新モデルは自動で有効になる」と記載する。Business / Enterprise は Copilot 設定のモデルポリシーで制御する
- ⚠️ Sol（$4／$20）比で入力・出力とも **2.5倍**にあたるモデルが、既定オンで従量課金の面に入った。09-04 収録の Gemini 3.8 Flash が「2026年12月31日まで introductory pricing」だったのに対し、**Astra には期間限定価格の記載がない**

### 3. Claude Code 2.1.261 が組織ポリシーの失敗を可視化した — スケジュール実行の修正は4版連続

**要点**: Claude Code 2.1.261 が9月4日に出た。組織ポリシーの読み込み失敗が `/status` と `claude doctor` に出るようになり、クラウドセッションがプラグインを取りこぼす不具合も直った。統制が「効かないまま気づけない」状態が減る。

**詳細**:

- 統制の可視化が本版の中心である。`/status` と `claude doctor` に **「Organization policy」行**が追加され、ポリシーが読み込めなかった場合にその理由が表示される。管理下設定の不具合修正も2件入り、フィーチャーフラグが誤ったバージョンの Claude Code に適用される問題と、信頼済みプロキシ配下でのゲートウェイのクライアント IP 取り扱いが対象である
- 出力量の制御に設定が2つ増えた。`bashOutputMaxChars` と `taskOutputMaxChars` で、いずれも **最大128K** まで指定できる。サブエージェント向けには `--append-subagent-system-prompt-file` が加わり、長いプロンプトをファイルで渡せるようになった
- `/skill-doctor` が追加され、使われていないスキルとそれが食っているコンテキスト量を洗い出せるようになった
- 権限まわりの修正は `/add-dir <subdirectory>` が `/net` の automount 上で誤ってエラーになる不具合と、Bedrock セットアップウィザードのタイムアウト処理である。Remote Control 側では権限モード・古い状態・セッション同期の修正が複数入った
- ⚠️ **スケジュール／クラウド実行環境の不具合修正が4版連続で続いている。** 2.1.258 は「remote / scheduled セッションが `user messages must have non-empty content` で失敗」、2.1.259 は「コネクタツールの権限承認後に応答しない」、2.1.260 は「クラウド上の claude.ai セッションで Claude in Chrome が `Not connected`」、2.1.261 は「管理下設定がプラグインを強制有効にしているとクラウドセッションが同期済みプラグインを捨てる」を修正した。**本ダイジェストの生成環境そのものが該当する系統**である
