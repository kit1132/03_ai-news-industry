### 2. GitHub Code Quality に一括の agentic autofix が GA — 指摘対応が1件ずつから25件単位に変わった

**要点**: GitHub Code Quality の指摘を**最大25件**まとめて Copilot に委任し、ブランチ上で自己検証させて PR を出させる機能が **GA** になった。個別の「Generate fix」は「Assign to Copilot」に置き換えられた。

**詳細**: 9月9日付で一般提供を開始した。1ページ上の standard findings を最大25件選択して一括で Copilot に割り当てると、Copilot がブランチ上で修正を進め、自分の変更を検証したうえでレビュー用の PR を開く。対象は **GitHub Team** と **GitHub Enterprise Cloud**（データレジデンシー版を含む）。専用のポリシーは新設されず、既存の GitHub Code Quality のエンタープライズポリシーをそのまま継承するため、Code Quality を許可している組織では追加の管理操作なしに利用できる。⚠️ **割り当てごとに AI クレジットを消費する**点は、9月1日に発効した Copilot の込みクレジット減額（Business が $30 → **$19**／Enterprise が $70 → $39）と直結する。一括委任は1回の操作で消費量が読みにくくなるため、クレジット枠の月次消化ペースを見る運用が要る。⚠️ 同日、シークレット混入 PR のマージを止める新ルールセット `Require secret scanning alerts are resolved` も **public preview** で入った（GitHub Secret Protection / Advanced Security 契約者向け）。push protection がプッシュ段階で止めるのに対し、こちらは PR 段階で「head コミットのスキャン完了」と「当該 PR のコミットが持ち込んだシークレットの未解決アラートがゼロ」の2条件を課す。REST API の `require_secret_scanning_alert_resolution` と GraphQL からも設定できる。

### 3. Meta が個人向けエージェント Muse を提供開始 — エージェントの隔離単位が「利用者1人ごとの VM」になった

**要点**: Meta が個人向けエージェント **Muse** を公開した。無料枠は週1億トークンで、有料は **$20** と **$100** の2段。利用者ごとの専用 VM に承認役エージェントを併置する構成で、個人エージェントの前提が「共有クラウド上のアシスタント」から外れた。

**詳細**: 9月8日、米国で iOS / Android / Web（muse.ai）向けに提供を開始した。WhatsApp からも呼び出せ、Meta の AI グラス対応も予告されている。メール送信・旅行予約・フォーム入力・購買を利用者に代わって実行する構成で、モデルは **Muse Spark**。実行基盤の Muse Secure VM は利用者専用のクラウド VM で、エージェント本体と当人のデータを同じ VM 内に収め、他人のエージェントから到達できないよう分離する。同じ VM 上で **Sentinel** と呼ぶ別のエージェントがシステムレベルで隔離されて動き、Muse の通信は Sentinel の承認を経ないと外部に出ない設計になっている。将来的には暗号鍵を利用者が単独で保持する Confidential VM を予定しており、Meta 自身の技術的なアクセスを排除するとしている。料金は無料・Power（月$20）・Maximum（月$100）の3段で、有料ティアが買うのは機能ではなく利用量。無料でも支払いカードの登録が要る。⚠️ **Power / Maximum の上限トークン数は未公表**で、公開されているのは無料枠の週1億トークンのみ。費用試算に使えるのは無料枠の数値だけである。⚠️ 一次の `about.fb.com` は本日ゲートウェイ拒否を確認したため、数値は二次複数件の突き合わせによる。
