### 1. M365 Copilot Business の従量課金が既定オンへ — 1人あたり月$10 の消費枠が付いてくる

**要点**: Microsoft が11月2日から、CSP 経由で新規購入する M365 Copilot Business を従量課金の既定オンにする。前提が「ライセンス費だけ見積もればよい」から「1人あたり月$10 の消費枠も併せて見積もる」へ変わる。

**詳細**: Partner Center の9月16日付告知。新規ライセンスには従量課金に必要な Azure サブスクリプションの設定が同梱され、パートナー側の多段階の課金設定作業が不要になる。Microsoft は狙いを「導入支援に時間を振り向けられること」と「初期利用から消費拡大・アップセルへの導線ができること」と説明している。⚠️ 一次の Learn ページ（`ms.date` 2026-09-10）と告知本文で**対象体験の一覧が食い違う**。Learn 側が従量課金で管理されるサービスとして挙げるのは Cowork・Cowork で作ったアプリ・Work IQ API の3つで、告知が挙げる GitHub Copilot Harness は含まれていない。⚠️ さらに Learn 側には、支出ポリシーの「新しいサービスを自動適用」設定が**既定で有効**と明記されている。今後 Microsoft が対象サービスを追加した場合、明示的に無効化していない組織では新サービスが自動的にポリシーの対象に入る。見積もりの前提として、対象体験は固定ではなく増える側に開いていると置くのが妥当になる。

- 発効日: 2026年11月2日
- 対象: CSP 経由の Microsoft 365 Copilot Business の新規購入（単体・バンドルとも）
- 既定上限: 1人あたり月 USD$10 のペイアズユーゴー。上限の変更と前払いクレジットの追加は可能
- 既存ライセンスへの遡及は告知に記載がなく、対象は新規購入に限られる
- https://learn.microsoft.com/en-us/partner-center/announcements/2026-september
- https://learn.microsoft.com/en-us/microsoft-365/copilot/usage-based-billing-overview-copilot-credits

### 2. Office LTSC 2021 が10月13日でサポート終了 — オンプレ版 Office は Copilot 対象外と明記された

**要点**: Microsoft が Office / Project / Visio LTSC 2021 のサポート終了を10月13日と告知した。前提が「Copilot はライセンスを足せば使える」から「オンプレ版 Office のままでは対象外」へ変わる。

**詳細**: Partner Center の9月15日付告知。終了後は更新・セキュリティ修正・技術サポートのいずれも提供されない。告知本文が明記したのは、**Microsoft 365 Copilot がクラウドバックされたアプリでのみサポートされ、オンプレミス版 Office は対象にならない**という点で、永続版 Office 向けの Azure Information Protection ラベリングクライアントも退役済みとされた。LTSC を使い続けている顧客に対しては、Copilot 提案の前段としてまずスイート移行が必要になる。規制・接続性・技術上の制約でクラウドに移れない場合の受け皿としては Office LTSC 2024 / Project LTSC 2024 / Visio LTSC 2024 が挙げられているが、この経路を採る限り Copilot は使えない。

- 企業向けの第一推奨は Microsoft 365 E3、代替は Office 365 E3 または Microsoft 365 Apps for enterprise
- 300ユーザー未満は Microsoft 365 Business Premium / Business Standard / Apps for business
- Project LTSC / Visio LTSC の後継はそれぞれ Planner and Project Plan 3 / Visio Plan 2 で、スイートに重ねて追加する
- https://learn.microsoft.com/en-us/partner-center/announcements/2026-september

### 3. Claude Code 2.1.273 が公開 — 組織の MDM 設定が無視される不具合が修正された

**要点**: Claude Code 2.1.273 で、MDM 配布の MCP 制限設定がサーバー管理設定と併存すると無視される不具合が修正された。前提が「管理設定を配れば効いている」から「2.1.272 以前は要確認」へ変わる。

**詳細**: 9月15日付で公開された。同じ9月15日付の 2.1.272（不具合修正と安定性改善のみ）に続く大型更新で、内容は**組織統制と権限チェックの修正**に寄っている。⚠️ 統制面の2件はいずれも「設定したのに効いていなかった」型にあたり、Claude Code を組織配布している場合は現行バージョンの確認が要る。⚠️ 09-16 の確認では「最新は 2.1.272」と記録していたが、本日読み直すと同じ9月15日付で 2.1.273 が掲載されていた（B-031 該当・9回目）。前日は最新エントリの日付まで一致していたため、**日付の比較だけでは検出できない取りこぼし**になる。

- MDM / `managed-settings.json` の `allowManagedMcpServersOnly`・`deniedMcpServers`・`disableClaudeAiConnectors` が、サーバー管理設定と併存すると無視されていた
- 組織が claude.ai 側で Skills を無効化しても同期済みスキルが使え続けていた。復元可能なゴミ箱へ移動するよう修正された
- `permissions.blockReadsOutsideWorkingDirectories` 下で、権限チェッカーが完全に解析できない Bash コマンドが確認を飛ばしていた。bypass モードでサブシェルが危険な `rm` を隠す経路も塞がれた
- 自動コンパクトがアドバイザーツールのターンを実サイズの約2倍で数えており、実ウィンドウの**約半分**で発火していた
- LLM ゲートウェイ向けに `x-claude-code-request-class` ほか5種のリクエストヘッダーが追加された（`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` でオプトイン）
- https://code.claude.com/docs/en/changelog
