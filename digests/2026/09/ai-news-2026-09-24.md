### 2. [廃止+破壊的変更] GitHub が SSH の `ssh-rsa` と旧鍵交換を退役 — 10月14日から段階的に接続できなくなる

**要点**: SHA-1 署名の `ssh-rsa` と `diffie-hellman-group-exchange-sha256` が退役し、**10月14日**からは 3072 ビット未満の RSA 鍵を新規登録できなくなる。古い Git クライアントや CI ランナーの SSH 接続は、ブラウンアウト日（11月4日・12月9日）に実際に失敗し始める。

**詳細**: 9月22日付の changelog で告知された。前日のダイジェストでは件名のみ記録していた項目を、個別エントリで日程まで確定させた。

- 10月14日: 新規 RSA 鍵は 3072 ビット以上が必須になり、耐量子の鍵交換 `mlkem768x25519-sha256` が有効化される
- 11月4日: `ssh-rsa` と `diffie-hellman-group-exchange-sha256` の1回目のブラウンアウト
- 12月9日: 2回目のブラウンアウト
- 完全削除: 原文は「**January 13, 2026**」と表記している。10月以降の日程の後に置かれており、時系列上は2027年の誤記とみられるが、一次の表記は修正せずそのまま示す

影響を受けるのは SSH と認証なし Git プロトコルの利用者だけで、HTTPS 接続は対象外。既存の RSA 鍵は、クライアントが `rsa-sha2-256` / `rsa-sha2-512` に対応していれば再生成は不要。GitHub は Ed25519 鍵への切り替えを推奨している。

- https://github.blog/changelog/2026-09-22-security-improvements-for-ssh

### 3. [セキュリティ+新機能] Claude Code 2.1.281 で `rm -rf "$(pwd)"` が auto mode でも確認を求めるように — 無確認の再帰削除が塞がれた

**要点**: 削除対象がコマンド置換の出力だけで決まる再帰 `rm` が、auto mode と `--dangerously-skip-permissions` で**確認なしに実行されていた**問題が修正された。Bash の allow ルールがあっても確認を求める。あわせて `"attribution": false` でコミット／PR の署名行を一括で消せるようになった。

**詳細**: 9月23日公開。権限まわりの修正は3点ある。

- 置換 `rm`: `rm -rf "$(pwd)"` のような削除は allow ルールがあっても確認する。`CLAUDE_CODE_DISABLE_SUBSTITUTION_RM_PROMPT=1` で従来動作に戻せる
- NUL バイト: NUL を含む権限ルールがワイルドカードとして展開されていた問題を修正し、何にも一致しないようにした
- macOS のネットワークマウント: `/.vol`・`/.nofollow`・`/.resolve` 配下のパスを承認前に読んでいた問題を修正した

組織向けには Claude apps gateway が拡張された。Bedrock 上流に `assume_role`（STS 経由で別アカウントの IAM ロールを引き受け、開発者ごとにセッションを分けることもできる）と `guardrail`（全リクエストに Amazon Bedrock ガードレールを適用）が追加された。`blockedMarketplaces` でプラグインマーケットプレイスをドメイン単位で拒否でき、Claude Desktop の `blockReadsOutsideWorkingDirectories` と `disableBypassPermissionsMode` も gateway のポリシーで配れるようになった。`claude plugin validate` は `.mcp.json` の読み込み時に黙って捨てられる項目と安全でない URL を報告する。⚠️ `"attribution": false` を書いた settings ファイルは**旧バージョンの CLI では丸ごと読み飛ばされる**ため、複数バージョンで共有するファイルではオブジェクト形式を使う。

- https://code.claude.com/docs/en/changelog
