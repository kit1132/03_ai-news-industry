### 1. [予定+動向] Google が業務用の Gemini agent を発表し、裏で Claude も選べるようにした — 「Gemini か Claude か」で社内ツールを選ぶ前提が崩れた

**要点**: Google Cloud が10月8日の Gemini at Work 2026 で、業務用の統合エージェント「Gemini agent」を発表した。作業ごとに Gemini と Anthropic の Claude から適したモデルを選んで動かす。基盤を Google に寄せても Claude を使えるため、モデルの比較はベンダー選定の決め手にならなくなった。

**詳細**: Google Cloud ブログ（一次）による。提供開始日と価格は書かれていない。

- 接続先: Gmail・Drive・Docs・Sheets・Calendar などの Workspace に加え、Microsoft 365・Slack・Jira・Salesforce・ServiceNow・BigQuery・Snowflake と任意の MCP サーバー
- エージェントの身元: 協働エージェントごとに Workspace アカウント（`@agents.company.com` のメール・カレンダー・Drive）を持たせる。操作はすべて監査ログに残り、人ではなくエージェントの操作として記録される
- 統制: 実行は個別のネットワーク境界を持つ Agent Sandbox の中で行う。出入りとエージェント間の通信は、AI 用ファイアウォールの Agent Gateway を通してポリシーを当てる
- 費用の上限: Cloud Billing Console でプロジェクトごとに AI 支出の上限を設定できる。上限に達するとエージェントが止まり、コンソールから1クリックで再開する
- 業種別版: 金融と法務はプレビュー、政府・医療・小売は今後
- 導入事例（Google 公表）: Commerzbank は文書レビューを20時間から1時間に、Bradesco は1時間から5分に短縮した。SOMPO は従業員3.4万人で1万超のカスタムエージェントを動かしている

- https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026
- https://blog.google/innovation-and-ai/infrastructure-and-cloud/google-cloud/gemini-at-work/

### 2. [セキュリティ+新機能] Claude Code 2.1.294 で、指示文で書いたフックが止めるべき操作を通していた問題が直った — 自然文フックで統制している環境は更新が要る

**要点**: Anthropic が10月8日に Claude Code 2.1.294 と 2.1.295 を出した。「〜するコマンドはブロックせよ」のように指示文で書いた `prompt`・`agent` フックが、止めるはずの操作を通すことがあった。フックで権限を絞っているなら、古い版のままだと統制が効いていない可能性がある。

**詳細**: 公式 changelog（一次）による。

- 2.1.294 の修正: 指示文で書いた `prompt`・`agent` フックが、ブロック対象の操作を許可してしまう問題を直した。Stop・SubagentStop の `prompt` フックの判定も改善した
- 2.1.295 の新機能: コマンド・HTTP フックに `onFailure: "block"` を追加した。フックが起動しない・タイムアウトする・異常終了するときに、操作を通さずに止める
- 2.1.295 のセキュリティ修正: 深い入れ子のツール入力が切り詰められたままフックに渡り、ガードが中身を見ずに通していた問題、mod の再読み込み中の呼び出しが他の mod のガードを迂回していた問題、改ざんされた設定キャッシュで個人のプラグインが組織管理として扱われていた問題の3件を直した
- 既定の変更: tool search で読み込む MCP ツールの説明の上限を 2,048字から 16,384字に広げた。claude.ai のコネクタは MCP プロトコル 2026-07-28 を既定で使う（`MCP_PROTOCOL_NEGOTIATION=legacy` で戻せる）

- https://code.claude.com/docs/en/changelog

### 3. [破壊的変更] Claude Managed Agents の `web_fetch` が、会話に出てきた URL しか取得しなくなった — 任意の URL を取りに行く設計のエージェントは動かない

**要点**: Anthropic が10月7日に、Managed Agents の `web_fetch` が取得できる URL を、そのセッションにすでに現れたものに限った。プロンプトの中で URL を組み立てて取りに行くエージェントは、エラーで止まるようになった。

**詳細**: リリースノート（一次）による。10-08 に同じ日付の他の項目を収録した際に取りこぼしており、1日遅れの捕捉。

- 取得できる URL: ユーザーのメッセージ、`web_search` の結果、取得済みのページに出てきた URL だけ
- それ以外: `url_not_in_prior_context` エラーを返す。取得させたい場合は、その URL を `user.message` で送る
- 同日の関連改定: `limited` ネットワークでは `allowed_hosts` が `web_search`・`web_fetch` にも効く（10-08 収録）。`allowed_hosts` を空にすると両ツールとも使えない

- https://platform.claude.com/docs/en/release-notes/overview
