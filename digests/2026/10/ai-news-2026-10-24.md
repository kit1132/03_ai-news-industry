### 1. [料金+新機能] Anthropic が Claude API を Google Cloud の請求で直接提供し始めた — GCP のコミットで Claude API 本体の機能が使える

**要点**: Anthropic が10月22日、自社運用の Claude API を Google Cloud プロジェクト経由で使える「Claude Models on Google Cloud (Anthropic managed)」を始めた。これまで GCP で Claude を使うには Google 運用の Vertex AI 版しかなかったが、Marketplace の請求と GCP の支出コミットのまま Anthropic 運用の API を選べるようになった。

**詳細**: 一次はリリースノート 10/22（2項目）と設定ガイド。

- 課金: Google Cloud Marketplace 経由。Anthropic が計量し、Claude Consumption Unit（1単位 $0.01）で GCP の請求書に載る。GCP の支出コミットに計上される。既存の割引は開始前に担当者へ連絡が必要で、過去の利用には遡らない
- 認証と組織: Google Cloud IAM のみで API キーは使えない。既存の Anthropic 組織（Claude Enterprise を含む）とは別の新組織が作られ、他組織の ZDR は引き継がれない（ZDR は申請制）
- 機能: Opus 5.5 の Fast mode も使える。退役日は Claude API と同じ表が適用される。MCP tunnels と、セルフホスト環境のメモリストア・SDK 付属のセルフホストワーカーは非対応
- ログ: Cloud Audit Logs の `claude.googleapis.com` に記録される。Data Access ログは既定オフ

- https://platform.claude.com/docs/en/release-notes/overview
- https://platform.claude.com/docs/en/build-with-claude/claude-models-on-google-cloud/anthropic-managed

### 2. [セキュリティ] Microsoft が中国系 Storm-0940 の AI エージェント攻撃を公表した — ConnectWise 経由で M365 テナントに侵入

**要点**: Microsoft が10月21日、中国政府と関係する Storm-0940 が AI 侵入フレームワーク「ARTEX」で数百組織を狙い、ConnectWise Cloud Backup の利用企業の Microsoft 365 に入り込んだと公表した。韓国の金融機関への攻撃で疑われていた ARTEX が、M365 の供給網攻撃に使われたことになる。

**詳細**: GIGAZINE と Reuters・CyberScoop の転載で確認した。Microsoft Security Blog の本文には到達していない。

- 規模: 2,250超のテナントが標的となり、毎分約2,900回のログインが試みられた。一部では標的化から3時間以内に特権を奪われた（3時間・2,250は二次1系統の数値）
- 手口: 327アカウントへのパスワードスプレーが失敗した後、ConnectWise Cloud Backup 顧客の M365 環境へ移り、エージェントが Microsoft Graph とディレクトリ操作、アプリ資格情報の変更による持続化まで進めた
- ARTEX: どの AI モデルでも動くオープンソースのペネトレーションテスト用フレームワークで、偵察からデータ持ち出しまで自律で実行できる。使われたモデルは公表されていない
- 対処: Microsoft は 10月15日以降（記録があれば10月1日以降）の活動と M365 監査ログの確認を求めた。Microsoft 自身のシステムの侵害ではないとしている

- https://gigazine.net/news/20261023-storm-0940-artex-cyber-attack/
- https://cyberscoop.com/?p=91224

### 3. [破壊的変更] Claude Code 2.1.309 で `claude ultrareview` にワークスペース信頼が必須になった — CI から呼ぶスクリプトは止まる

**要点**: Anthropic が10月22日に出した Claude Code 2.1.309 で、`claude ultrareview` は信頼済みのワークスペースでしか動かなくなった。端末なら確認が出るが、端末の無い CI では拒否されるため、スクリプトに `--trust-workspace` を足す作業が要る。

**詳細**: 一次は Claude Code changelog（2.1.309、10/22）。

- `ultrareview`: スクリプトは `--trust-workspace`（値を取らないため PR 番号やベースブランチはその前に置く）を渡すか、`CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1` を設定する
- `sed -i`: 擬似的な編集プレビューをやめ、通常の Bash 確認で実行する。他の Bash 編集と同じく `/rewind` では戻らない
- bypass permissions モード: Desktop・VS Code では危険な `rm`/`rmdir` を確認なしで即時拒否し、書き換え案を返す
- サンドボックス修正: macOS・Linux でシェルの起動ファイルがサンドボックス外で実行されていた問題、`--mcp-config` の設定ファイルを書き換えられた問題などを直した

- https://code.claude.com/docs/en/changelog
