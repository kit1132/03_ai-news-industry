### 1. [破壊的変更+予定] GitHub が `pull_request_target` の既定ブロックを12/2へ延期 — 11/9と11/16に2時間ずつ前倒しで止まる

**要点**: GitHub は公開リポジトリで `pull_request_target` を既定でブロックする開始日を、当初の11/2から12/2へ延期した。その前の11/9と11/16に2時間ずつブロックを試す（ブラウンアウト）。11/2開始と見込んでいた準備期限は11/9に変わり、何もしなければ fork からの PR を処理するワークフローがこの時間帯に失敗する。

**詳細**: GitHub changelog（11/2）は「Enforcement was previously scheduled for November 2, 2026」と書き、延期の理由は示していない。

- ブラウンアウト: 11/9・11/16 の 16:00〜18:00 UTC（日本時間 翌1:00〜3:00）。ブロックされた実行はエラー注釈付きで失敗し、終了後は評価モードに戻る
- 対象: Free・Team・Enterprise Cloud の公開リポジトリ。private / internal と GitHub Enterprise Server は対象外
- 対応: Insights でブロック対象の実行を確認し、既定のブロックを受け入れるか、Actions のイベントポリシーで `pull_request_target` を明示的に許可する（ワークフローファイル単位の指定も可）

- https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2

### 2. [セキュリティ] 改ざん版 Claude Code 拡張は 2.1.312・2.1.313 — アンインストールだけでは SSH 鍵と自動起動が残る

**要点**: 10/29 に Cursor のマーケットプレイスで配布された改ざん版は、Claude Code 拡張の 2.1.312 と 2.1.313（macOS・Windows）だった。攻撃者の SSH 鍵と自動起動の設定を書き込むため、拡張を消しても侵入口は残る。「拡張を消せば済む」という前提は成り立たない。

**詳細**: Cursor の告知（10/30 更新）、Phorion の分析（10/30）、GIGAZINE（11/2）で拡張の版と対処手順が出た。10-31 時点では拡張の版も IOC も公表されていなかった。公開時間は 10/29 2:27〜13:35 PT（日本時間 18:27〜翌5:35）で、影響人数はどの一次にも書かれていない。Anthropic は公式経路で配布した Claude Code は無事だと説明した。

- 確認: `~/.ssh/authorized_keys` に `svc-telemetry` の鍵があるか（Windows は `administrators_authorized_keys` も見る）
- 除去: 不正な鍵、`~/.config/.smt`・`.smtk`、LaunchAgent `com.apple.sysmond.plist`（macOS）または `SysMon` タスクと `sysmon.cmd`（Windows）を消し、`ssh -R` / `autossh` のトンネルを止める
- 修復スクリプト: macOS は `remediate-macos.sh`、Windows は `remediate-windows.ps1`。何か残っていると終了コードが0以外になる
- その後: 該当端末から使えた認証情報とセッションを、安全な別の端末から更新する。Cursor は端末の再構築も検討するよう求めている
- 収集されていた情報: PC 名・ユーザー名・OS・公開 IP・Git のメールアドレス・環境変数名。環境変数の値が送られた形跡は見つかっていない
