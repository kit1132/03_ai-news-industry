### 2. [仕様+予定] Claude の透かしが 11/16 から Opus 4.5・Sonnet 4.5・Haiku 4.5 にも入る — サンプリング設定を変えると付かない

**要点**: Anthropic は API 利用者へのメールで、11/16 から Opus 4.6・Opus 4.5・Sonnet 4.5・Haiku 4.5 の出力にも透かしを入れると伝えた。4モデルとも `temperature`・`top_p`・`top_k` が既定値のときだけ付く。透かしは「Claude の出力すべてに付く」ものから「設定しだいで付かない」ものに変わり、コンプライアンスの根拠には使いにくくなった。

**詳細**: 11/3 付のリリースノートは、透かしの対象を Mythos 5・Opus 4.7・Sonnet 4.6 と書いている。10/31 のメールで第1弾に入っていた Opus 4.6 は理由の説明なく延期され、第2弾に回った（The Decoder 11/4 によるメール内容の紹介）。

- 第1弾（11/3）: Mythos 5・Opus 4.7 は設定にかかわらず付き、Sonnet 4.6 は既定値のときだけ付く
- 第2弾（11/16）: Opus 4.6・Opus 4.5・Sonnet 4.5・Haiku 4.5。4モデルとも既定値のときだけ付き、Amazon Bedrock は数日遅れる場合がある
- 理由: 12月の EU AI Act の期限。8/2 以降に出たモデルは最初から透かしが入っている
- Anthropic の案内: 「透かしをコンプライアンスに使うなら設定を既定値のままにする」。抜け道を塞ぐとは書いていない

- https://platform.claude.com/docs/en/release-notes/overview
- https://the-decoder.com/anthropics-text-watermark-is-easy-to-bypass-on-several-older-claude-models/

### 3. [破壊的変更+新機能] Claude Code 2.1.318 から IDE のターミナルで起動しても拡張機能が入らない — サインインの期限切れは10日前に警告

**要点**: Anthropic が 11/4 に公開した Claude Code 2.1.318 では、IDE のターミナルから起動しても VS Code などの拡張機能を入れたり更新したりしなくなった。「起動すれば拡張機能も最新になる」という前提が無くなり、更新は `/ide` か IDE の拡張機能画面から行う。

**詳細**: そのほかの主な変更は次のとおり。

- サインインの期限: `claude auth status` に `loginExpiresAt`、`claude -p` の JSON に `credential_expires_at` が加わった。`claude -p` は期限の10日前から stderr に1行の警告を出す
- gateway: `mantle` 上流に `assume_role` を設定でき、別の AWS アカウントのロールを使って開発者ごとに AWS 費用を割り振れる
- Managed Agents: `/claude-api managed-agents-onboard` で作るエージェントの組み込みツールが、既定で `auto` 権限ポリシー（危険な操作を判定）になった
- cloud sessions: リポジトリを選ばずにセッションを始められる
- self-hosted runner: ログの書式が変わった。`retryable=true:` や `retryable=false:` に一致させているスクリプトは直す必要がある

- https://code.claude.com/docs/en/changelog
