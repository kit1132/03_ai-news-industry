## 今日のハイライト

### 1. [セキュリティ] Claude Code がアカウントのメールアドレスを外部サイトへ送っていた — 7月から報告があり、対策は 2.1.317 以降だけ

**要点**: Claude Code が、ユーザーのメールアドレスを HTTP リクエストの User-Agent に入れ、`curl` などで呼んだ外部サイトに送っていたことが分かった。最初の報告は7月17日で、対策が入ったのは11月3日の 2.1.317 からになる。それより前の版で使っていた環境では、すでに外部へ送られている可能性がある。

**詳細**: GIGAZINE（11/6）が GitHub Issue（#78431・#81138・#107757）をもとに経緯をまとめた。changelog（2.1.317・11/3）には「Web やシェルのツール呼び出しがアカウントのメールアドレスをネットワークへ送る前に確認する」機能の追加が載っている。

- 経路: アカウントのメールアドレスがシステムプロンプトに入っていた（7/25 の報告）。連絡先を求めるサイト（crates.io など）の方針に従って、Claude が User-Agent に入れた可能性が指摘されている
- 規模: 1時間のセッションで5回、別の報告者は1カ月で10回以上送られ、送り先には米 SEC も含まれていた。名前・所属企業・リポジトリ名まで入っていた例もある
- 対策: 開発メンバーは 11/5、2.1.317 以降に既定で有効なプラグイン `cc-plugin-privacy` を入れたと説明した。`/plugins` で有効かを確かめられる。報告者の一部は、仕組みごと消すべきだと主張している

- https://gigazine.net/news/20261106-claude-code-mail-address/
- https://code.claude.com/docs/en/changelog

### 2. [破壊的変更+新機能] Claude Code 2.1.319 で、LLM ゲートウェイ越しの auto mode が組み込み判定に戻らなくなった — 確認できない操作は質問か拒否になる

**要点**: Anthropic は 11/6 に Claude Code 2.1.319 を出した。テレメトリや機能フラグを切った環境と LLM ゲートウェイの裏では、auto mode がサーバー側で確認できない操作を、組み込みの判定で通さずに質問するか拒否する。ゲートウェイ経由で無人実行している環境は、止まる場面が増える。

**詳細**: changelog（2.1.319・11/6）で確認した。Added 18件・Changed 26件・改善16件・修正90件の大型更新になる。

- 戻し方: `CLAUDE_CODE_AUTO_MODE_SERVER=0` で従来の組み込み判定を使い続けられる。Bedrock・Vertex・Foundry は変わらない
- `permissions.denyInsteadOfPrompting`: 許可の確認待ちになる操作を拒否して、ターンを続ける設定が加わった。ターミナル・サブエージェント・チームメイトで効く
- `/loop`: 自分でペースを決めるループは、再予約なしでターンが終わると止まるようになった。従来の動きは `CLAUDE_CODE_LOOP_KEEPALIVE=1` で残せる
- Claude apps gateway: 今日・今週・今月の支出が `/usage` に出るようになり、複数のグループ予算から払う順番を設定できる。11月10日の Claude Desktop の変更に向けた警告も入ったが、変更の中身は書かれていない

- https://code.claude.com/docs/en/changelog
