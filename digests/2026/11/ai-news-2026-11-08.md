## 今日のハイライト

### 1. [新機能+仕様] Copilot code review の Balanced effort が3モデル構成になり、設定を API で管理できるようになった — レビューの中身と管理の手段がどちらも変わった

**要点**: GitHub が 11/6 に Copilot code review を更新した。Balanced effort のレビューは、3つのモデルが見た結果を別のモデルがまとめる形に変わった。Enterprise・組織・リポジトリの設定も API で読み書きできるようになり、画面で1つずつ設定していた管理を一括で済ませられる。

**詳細**: GitHub changelog（11/6）で確認した。対象は Copilot Pro・Pro+・Max・Business・Enterprise で、料金の改定は書かれていない。

- API の権限: Enterprise 管理者は全組織の有効・無効を決めるか組織に任せられる。組織管理者は有効化・既定の effort・runner を、リポジトリ管理者は effort・カスタム指示・MCP ツールの使用を管理できる
- API の制限: Enterprise と組織の設定エンドポイントは GitHub App と fine-grained PAT に対応していない。リポジトリ用は両方に対応し、Classic PAT にはリポジトリ管理者の権限が要る
- 出力の識別: API で Copilot のレビューとコメントを見分けられ、使われた effort、コメントの元になったスキル・MCP サーバー・カスタム指示も取れる
- 費用の表示: レビューで消費した AI クレジットが、コードレビューエージェントのセッションに出るようになった
- 自動再試行: 失敗やタイムアウトのときは1回だけ再試行し、優先モデルが使えなければ別のモデルに切り替わることがある
- 自動レビューのリポジトリルールにバイパスリストが加わり、リストにある人やアプリは自動レビューを受けない

- https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates

### 2. [新機能] Slack と Teams の `@GitHub` が一般提供になった — 会話の中で Issue 作成から PR 作成まで進められる

**要点**: GitHub が 11/6、Slack と Teams から Copilot に作業を頼む `@GitHub` を一般提供にした。バグ調査・Issue 作成・実装・PR 作成を会話を離れずに進められ、Teams では計画やコード変更を並べて見る Canvas も使える。チャットでの依頼から PR までが、管理された正式機能として使えるようになった。

**詳細**: GitHub changelog（11/6）で確認した。対象プランと課金（AI クレジットの扱い）は書かれていない。

- Canvas（Teams）: 会話と並べて実装計画・コード変更・プレビューを確認し、チームで共有して直していける
- 開始の手順: メッセージからリポジトリを自動で特定し、選び直さずにセッションを始められる
- 作成元の記録: `@GitHub` が作った Issue や PR の説明に、Slack・Teams の会話から作られたことと、会話したユーザー名が入る

- https://github.blog/changelog/2026-11-06-github-copilot-in-slack-and-teams-is-generally-available
