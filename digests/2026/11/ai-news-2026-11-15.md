### 2. [破壊的変更+セキュリティ] Claude Code 2.1.325 でサンドボックス内の Bash も確認を求めるようになった — 無人実行のスケジュールタスクは設定を足さないと止まる

**要点**: Anthropic が Claude Code 2.1.325（11/13）で、サンドボックス内の Bash コマンドを自動許可せず、通常の権限確認に通すよう既定を変えた。スケジュールタスクと `/loop` も `allowed-tools` やフックを宣言したスキルの前で確認を求めるため、無人で回していた運用は許可設定の追加が前提になった。

**詳細**: Claude Code の changelog で一次確認した（2.1.324 は欠番）。

- サンドボックス: 従来の挙動に戻すには `sandbox.autoAllowBashIfSandboxed: true`。サンドボックスを有効にする管理設定では、最上位の管理ソースに書く必要がある
- スケジュールタスク: 該当スキルを無人で動かすには `permissions.allow` に `Skill(name)` を加える。Desktop・IDE・SDK の「Always allow」も、保存すると同じコマンドが再び許可される場合にだけルール単体を出すよう変わった
- git: プロジェクト外で未信頼のリポジトリでは、読み取り専用の git コマンドも確認を求める。許可するには `--add-dir` で指定する
- 修正: zstd 圧縮レスポンスのデコードのセキュリティ問題、複合 Bash コマンドの権限チェック漏れ、allow ルールが別のプログラムを実行しうる問題を直した。サードパーティのゲートウェイや Foundry で毎ターン context length エラーになる問題も直っており、2.1.323 の 1M 既定化の副作用に当たる

- https://code.claude.com/docs/en/changelog
