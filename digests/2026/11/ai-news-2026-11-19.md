### 1. [セキュリティ] OpenJDK に CVSS 9.2 の脆弱性 Java4Shell、Codex が約1時間で発見 — Jenkins・Jira などが認証なしで乗っ取られうる

**要点**: OpenJDK の Base64 デコーダにメモリ破損の脆弱性（CVE-2026-114938）が見つかり、Oracle が 11/17 に修正を出した。発見者は OpenAI の Codex を使い、発見に約1時間、攻撃コードに約2時間、トークン費用は $200 未満だった。AI による脆弱性の発見から悪用までの時間は、時間単位まで縮んだ。

**詳細**: GIGAZINE（11/18）が、研究者 Quang Luong 氏（Calif）の公表と OpenJDK・Oracle の勧告をもとに報じた。

- 影響範囲: 未修正の OpenJDK 17.0.6 以降と、それを元にする Amazon Corretto・Eclipse Temurin・Microsoft Build of OpenJDK・Oracle Java SE。AVX-512 VBMI 対応の x86-64（Intel Xeon Ice Lake 以降の一部、AMD Zen 4 以降）だけが対象で、ARM64 は影響を受けない
- 実証: Keycloak・Jira・Confluence・JFrog Artifactory・Jenkins・PingFederate の既定構成で、認証なしの遠隔コード実行が示された。Kafka・Solr・Elasticsearch などは認証ありで成立する
- 当面の回避策: Base64 デコードの AVX-512 高速化を無効にする。修正版の番号は記事に書かれていない

- https://gigazine.net/news/20261118-java4shell/

### 3. [破壊的変更] Claude Code 2.1.327 が auto mode の課金付き判定フォールバックの廃止を予告した — 判定できない操作は承認待ちか拒否になる

**要点**: Claude Code 2.1.327（11/17）で、auto mode が課金付きの分類リクエストへ切り替える際の通知に「次のリリースでこのフォールバックを削除する」と明記された。削除後は、判定できない操作が確認を求めるか拒否される。無人で回している auto mode の処理は止まる場面が増える。

**詳細**: 一次（code.claude.com の changelog）で確認した。

- `permissions.blockReadsOutsideWorkingDirectories`: bypass・auto モードで確認を求める Bash コマンドが増え、Read・Edit の deny ルール配下のパスを指すコマンドは確認ではなく拒否になった
- auto mode: `Bash(pnpm dlx *)` のような任意パッケージを実行する許可ルールを無視する範囲が広がった
- 変数展開で非常に長くなる Bash コマンドは拒否される。`ExitWorktree` は未保存の作業がありうるワークツリーを消す前に確認する
- 追加: `claude mcp add-json <name> -`（トークンをコマンドラインに出さずに標準入力から設定を読む）、`/status` に壊れたエージェント・スキル定義や効かないフックの一覧、`attributionProject` で課金グループ名を付ける設定

- https://code.claude.com/docs/en/changelog
