## 今日のハイライト

### 1. [破壊的変更+新機能] Claude Code 2.1.329 で保存済みの定期タスクが再登録を要するようになった — Code Mode でフックがエラーになっても操作が止まらなくなった

**要点**: Claude Code 2.1.329（11/19）で、旧版が保存した定期タスクの多くは新しいサインイン済みセッションで登録し直しが必要になった。Code Mode では、エラーになった PreToolUse フックがスクリプトのツール呼び出しを拒否しなくなった。フックのエラーで操作を止める前提は、もう成り立たない。

**詳細**: 一次（code.claude.com の changelog）で確認した。2.1.327 が予告した「課金付き分類フォールバックの削除」は、2.1.329 の変更点にも書かれていない。

- 定期タスク: 旧版で保存したタスクの多くは再登録が必要になった。自分のセッションを `--resume` で再開した場合は、そのまま動く。「Exit and stop tasks」で終了すると、再開時にも定期タスクが動かなくなった
- Code Mode のフック: PreToolUse フックがエラーになっても、スクリプトのツール呼び出しは拒否されない（Code Mode 外と同じ扱い）。必ず拒否したいフックには `"onFailure": "block"` を付ける
- `max_tokens` の自動再試行: 2.1.326 で入った再試行を削除した。出力トークン上限の小さいゲートウェイ経由で使う場合は、`CLAUDE_CODE_MAX_OUTPUT_TOKENS` にその上限を設定する
- `/code-review`: 対象を指定しないと、ブランチ全体を既定ブランチと比べてレビューするようになった。`gh pr diff` が失敗したときは、レビューせずに止まる
- その他: フォルダーの信頼ダイアログが、フックの宣言場所を示すようになった。管理者設定のフックが読み込めないとき、会話に警告が出る。Code Mode は、テレメトリや機能フラグを切った環境でも起動するようになった（管理者設定で無効化できる）

- https://code.claude.com/docs/en/changelog
