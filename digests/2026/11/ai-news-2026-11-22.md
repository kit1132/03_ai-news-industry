## 今日のハイライト

### 1. [破壊的変更+新機能] Claude Code 2.1.330 で `deniedMcpServers` の名前指定が1コネクタしか止めなくなった — 定期タスクは最長30日まで延びた

**要点**: Claude Code 2.1.330（11/20）で、`deniedMcpServers` に名前で書いた拒否が、同じ URL の他のコネクタを止めなくなった。名前指定だけで同じ URL をまとめて塞いでいた組織では、その遮断が効かなくなる。2.1.329 で消した `max_tokens` の自動再試行は元に戻った。

**詳細**: 一次（code.claude.com の changelog）で確認した。2.1.327 が予告した「課金付き分類フォールバックの削除」は、今回も変更点に書かれていない。

- `deniedMcpServers`: 名前指定は、その名前の claude.ai コネクタだけを隠す。同じ URL のコネクタをすべて止めるには、URL を正確に指定して拒否する
- 定期タスクと `/loop`: セッションが動いている間は、7日ではなく最長30日動き、終わる日を表示する。この版より前に作ったタスクは7日で終わる
- `rm`: ルート・ホーム・最上位フォルダー・作業フォルダーを狙うコマンドの多くに、承認が必要になった。応答できる人がいない環境では拒否される
- `max_tokens`: 2.1.329 で消した自動再試行を元に戻した。前日に案内した `CLAUDE_CODE_MAX_OUTPUT_TOKENS` の設定は、必須ではなくなった
- その他: Anthropic の Enterprise Admin Console で管理する組織へのサインインに対応した。グラフを描く組み込み mod「easel」が入った（`/config` で自動描画を切れる）。`model` を指定したスキルは、サブエージェント・フォーク・圧縮をセッションのモデルのまま動かすようになった

- https://code.claude.com/docs/en/changelog

### 2. [破壊的変更] GPT-6.2 への移行では `temperature`・`top_p` を外す必要がある — 推論の強さ `none`・`minimal` は `low` に置き換える

**要点**: OpenAI の GPT-6.2 移行ガイドによると、Astra・Sol は `temperature`・`top_p`・`top_logprobs` を受け付けない。モデル名を差し替えるだけでは、既存のリクエストはそのまま動かない。11/17 の changelog は移行ガイドを示しただけで、外すパラメーターの一覧は今日はじめて確認した。

**詳細**: 一次（developers.openai.com の最新モデルガイド）で確認した。The Decoder（11/21）が、同じガイドのプロンプト指針を報じている。

- 外すパラメーター: Chat Completions では `temperature`・`top_p`・`logprobs`・`top_logprobs`、Responses では `temperature`・`top_p`・`top_logprobs` を外し、`include` から `message.output_text.logprobs` も除く
- 推論の強さ: 新しく組むなら `medium` から始める。`none`・`minimal` を使っている場合は `low` にする
- ツール呼び出し: Chat Completions も使えるが、ツール呼び出しは Responses API だけで動く
- プロンプトキャッシュ: 最上位の `instructions` にある固定の指示を、`input` 先頭の developer メッセージに移すとキャッシュの対象になる
- プロンプト: Astra は既定で簡潔に答える。「簡潔に」の指示は外す。権限の範囲内の手順は確認を待たずに進めるよう指示すると、余計な確認の質問が減る

- https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.2-astra
- https://the-decoder.com/openai-shares-new-prompting-tips-for-gpt-6-2-astra-and-sol-to-fix-brief-answers-and-unnecessary-questions/
