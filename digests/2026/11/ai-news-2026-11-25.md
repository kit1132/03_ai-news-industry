# AI ニュースダイジェスト 2026-11-25

## 今日のハイライト

### 1. [料金+新機能] Anthropic が PR のレビュー・修正・承認をまとめる「Claude Ship」を出した — Claude が PR を承認する運用ができたが、PR Steward は上限を設定するまで費用が青天井になる

**要点**: Anthropic が 11/24、Team・Enterprise 向けに Claude Ship を出した。Code Review・PR Steward・Claude Approvals の3エージェントで PR の修正と承認判断まで回す。費用はプラン枠外のトークン課金で、PR Steward は管理者が上限を設定するまで費用に上限がない。

**詳細**: Claude Code ドキュメントの「Claude Ship」ページと、The Decoder（11/24）による。

- Code Review: 一般提供。重大度順のインラインコメントで問題を指摘する
- PR Steward: パブリックベータ。失敗したチェック、マージ競合、レビューコメントに対して修正コミットを push する。承認やマージはしない設計
- Claude Approvals: パブリックベータ。`.claude/approvals.yml` のポリシーで、パスごとに必要な人数と Claude が承認してよい範囲を決める。GitHub の自動マージかマージキューを使い、人の承認を求めないポリシーにすると、誰も操作しないままマージされる
- 課金: どのエージェントも使用量クレジット（プラン内の利用枠とは別）でトークン課金される。Approvals はオブザーブモードでも課金される。組織設定で使用量クレジットを止めても、有効なエージェントは動き続けて課金される
- 既存の Code Review 利用者への影響: 設定は「Organization settings > Claude Ship」に移った。既定ブランチに `approvals.yml` を置くと、`claude/code_review` を指定したルールがないパスでは自動レビューが止まる
- 対象外: データ保持ゼロ（ZDR）・HIPAA 構成・顧客管理の暗号鍵を使う組織。対象の Enterprise 組織はプロモーション用のクレジットを申請できる

- https://code.claude.com/docs/en/claude-ship
- https://the-decoder.com/anthropics-claude-ship-lets-ai-agents-review-fix-and-approve-pull-requests-on-their-own/

### 2. [破壊的変更+予定] GitHub が 12/1 から使用量レポートに `user_id` 列を加える — 列の位置で読む集計スクリプトは12月分から列がずれる

**要点**: GitHub が 11/23、使用量レポートの `username` 列の隣に `user_id` 列を 12/1 から加えると告知した。後ろの列はすべて1つ右にずれる。Copilot の AI 使用量やプレミアムリクエストを列の位置で集計しているスクリプトは、12/1 までに見出し名で読むよう直す必要がある。

**詳細**: GitHub changelog（11/23）による。

- 対象レポート: 詳細使用量レポート、AI 使用量レポート、プレミアムリクエスト使用量レポート、REST API によるエクスポート。集計版の使用量レポートは対象外
- 対象プラン: GitHub Enterprise Cloud の全アカウント種別と、GitHub Team の単独組織
- ほかの変化: 削除済みアカウントの使用量は、空のユーザー名で1行にまとめず別々の行で出す。行ごとに丸めるため、合計値が小数点以下の末尾でわずかに変わることがある

- https://github.blog/changelog/2026-11-23-usage-reports-will-include-a-user-id-column-starting-december-1
